# G3.2 — Pump liveness delegates to runner list

## Spec

Make the supervisor's liveness question go through the runner when it can:

- At pump start, probe the configured runner once for `list` support (call it;
  exit 0 or the documented empty case means supported; "unknown verb" non-zero
  means v1 runner). Cache the answer for the run.
- `apl_live_agents` delegates to `runner.sh list` when supported, filtering to
  the configured prefix; otherwise the existing docker-prefix enumeration.
- Fail-open discipline mid-run: if a supported runner's `list` errors on a
  tick, log one warning and fall back to prefix enumeration for that tick —
  liveness going dark must never wedge the pump or mass-reclaim claims (a
  false "everything died" would trigger resume on every running task).
- Update PUMP-MECHANISMS.md §2: the mechanism is unchanged (process state over
  task status); only the enumeration source is now pluggable.

## Scope

`lib/pump-lib.sh`, the pump's call sites, tests, PUMP-MECHANISMS.md §2. The
monitor and cleanup keep prefix enumeration for now — they are read-only
observers and can migrate later.

## Acceptance

- `test-pump-lib.sh`: runner-backed liveness with a stub runner (populated,
  empty), v1-runner fallback, and the mid-run-error single-tick fallback, each
  asserting no claim is reclaimed spuriously.
- A drain with the claude-docker runner behaves identically before and after
  (its `list` is the same docker filter).
