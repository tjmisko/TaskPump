# G3.2 — Pump liveness delegates to runner list

## Spec

Make the supervisor's liveness question go through the runner when it can:

- At pump start, probe the configured runner once for `list` support (call it;
  exit 0 or the documented empty case means supported; "unknown verb" non-zero
  means v1 runner). Cache the answer for the run.
- `apl_live_agents` delegates to `runner.sh list` when supported, filtering to
  the configured prefix; otherwise the existing docker-prefix enumeration.
- Fail-open discipline mid-run: if a supported runner's `list` errors on a
  tick, log one warning and fall back to prefix enumeration for that tick —
  liveness going dark must never wedge the pump or mass-reclaim claims (a
  false "everything died" would trigger resume on every running task).
- Update PUMP-MECHANISMS.md §2: the mechanism is unchanged (process state over
  task status); only the enumeration source is now pluggable.

## Scope

`lib/pump-lib.sh`, the pump's call sites, tests, PUMP-MECHANISMS.md §2. The
monitor and cleanup keep prefix enumeration for now — they are read-only
observers and can migrate later.

## Acceptance

- `test-pump-lib.sh`: runner-backed liveness with a stub runner (populated,
  empty), v1-runner fallback, and the mid-run-error single-tick fallback, each
  asserting no claim is reclaimed spuriously.
- A drain with the claude-docker runner behaves identically before and after
  (its `list` is the same docker filter).

## Completion notes (2026-08-13T22:58:09Z)

Pump liveness delegates to `runner.sh list`.

What landed
- lib/pump-lib.sh: apl_runner_list_supported (cached capability probe),
  apl__runner_list (passes only the prefix + runtime, the two inputs `list` may
  read), apl_live_agents (the pluggable enumeration), apl_live_agent_slugs now
  built on it. Opt-in is APL_LIVENESS_RUNNER, set in-process by the caller —
  deliberately NOT derived from TASKPUMP_RUNNER, because the monitor, cleanup and
  both watchdogs load the same config and would have switched silently. Per the
  task's scope they keep scraping.
- libexec/tp-pump: sets APL_LIVENESS_RUNNER, probes once at startup in the MAIN
  shell (every tick reads liveness from a subshell, where a lazily-cached answer
  would not survive) and logs which source is in use. phase_live reads the
  pluggable enumeration.
- Probe semantics: exit 2 = "no such verb" = v1 runner. Any OTHER non-zero means
  the runner has the verb and its runtime is unreachable right now, so it still
  counts as supported. Misreading a startup blip as a v1 runner would scrape for
  the rest of the run, which for a non-container runner means every agent stays
  invisible until restart.
- Fail-open with a flag, not silently: a mid-run list failure still PRINTS the
  fallback scrape (liveness going dark must never wedge the pump) but returns 75.
  The two absence-driven passes — reclaim_orphaned_claims and
  detect_stalled_orphans — return early on that status via a new live_slugs()
  wrapper, warning once per tick. This is the "must never mass-reclaim" clause in
  the spec: for a non-container runner the fallback answer is EMPTY, so a single
  blind tick would release every claim in the range and resume every phase.
  The launch path deliberately keeps using the degraded answer — being wrong
  there costs one redundant decision the next tick corrects.
- docs/PUMP-MECHANISMS.md §2 gains "Where the pump looks": mechanism unchanged
  (process state over task status), source now pluggable, plus the fail-open /
  refuse-to-act asymmetry. CHANGELOG Unreleased updated.
