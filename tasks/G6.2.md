# G6.2 — Ledger text reaches the operator's terminal as text

## Spec

The dashboard is the control loop. An operator decides whether a multi-day drain
is healthy by reading `tp task list`, `tp monitor`'s SESSIONS panel and a
`tail -f .taskpump-agent.log | tp stream-fmt` feed — and all of that text is
written by somebody else: a task title out of the ledger, a branch out of a
claim, a feed line out of whatever an agent narrated over whatever a repository
contained. A terminal is an interpreter. `\033[2K\r` erases the line the
operator is reading and writes a different one, `\033[1A` walks back over a real
failure row, `\033[8m` hides text, an OSC rewrites the window title. Nothing
here executes code; this is display forgery, and a forged dashboard is how a red
run reads green for a day.

Issue: **#89**. It has four findings (PI-D8, PI-E1, PI-E2, PI-E8) and they are
one task because they are one sanitiser applied at four sinks.

**Half of this landed in the 2026-08-19 sweep — read the tree first.**
`lib/tty-safe.sh` now exists and defines `tp_display_safe <string>` (result in
`TP_SAFE`): TAB becomes one space, every other C0 byte and DEL is dropped, C1 is
dropped in both its UTF-8 and bare-8-bit encodings, and well-formed UTF-8 is
untouched so the *words* survive. `libexec/tp-stream-fmt` and
`libexec/tp-monitor` already source it. Every file:line in the issue body is a
starting point for a search, not a coordinate.

What must be true after:

### `libexec/tp-task` — the ledger's own renderer

`tp task list` prints `id`/`status`/`title` straight from `fm_get` (the issue
cites `:820-821`), and yq decodes a YAML `\e` escape, so the ledger is a
control-byte channel. Route that site and the other `fm_get`-to-stdout sites
through `tp_display_safe`. **`--json` output keeps the raw bytes** — JSON
escapes them and machine consumers must stay byte-identical. That split is the
whole design: the human surface is sanitised, the machine surface is verbatim.

### `libexec/tp-dag-render` — node labels

The renderer prints the same ledger values into the GRAPH view and into
`--claims`. Sanitise its node labels on the display path with the same helper,
for the same reason and with the same `--json`/TSV exception where a machine
consumer reads it.

### `libexec/tp-monitor` — sanitise before the slice

The monitor already sources `tty-safe.sh`, but the finish matters: sanitisation
must happen in `sessions_compute` **before** the record is written to the cache
and before the byte slice that truncates a feed line to the panel width, or a
truncation can cut an escape sequence in half and leave the terminal in a state
neither the payload nor the tool intended. Cover the feed lines, the raw-`tail`
fallback used before any stream-json record exists (it prints the entrypoint's
own `Goal: …` line, i.e. the ledger's `goal` field), `${goal:-}`, the
needs-attention rows and `session_header`'s name/task/branch.

### `libexec/tp-stream-fmt` — no `echo -e` anywhere

Every print must be `printf`, not `echo -e`. The amplification is the point: a
literal backslash-e in a log file is two harmless characters until `echo -e`
turns it into a real ESC, so the tool manufactures the attack out of input that
contained no control byte at all. Verify with `rg -n 'echo -e' libexec/tp-stream-fmt`
returning nothing.

### `lib/tty-safe.sh`

Only if the four sinks need something the contract does not yet give them (a
column budget, a variant that keeps LF for multi-line bodies). Extend it; do not
fork it. The file's stated discipline is one rule in one place, and four
renderers disagreeing about what is printable is the failure it exists to
prevent.
