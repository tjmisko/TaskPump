# G4.5 — Suites are hermetic against pump-exported ledger environment

## Spec

Issue #18: the pump/entrypoint export `TASKPUMP_TASKS_DIR` / `TP_TASKS_DIR`
(pointing at the real ledger) into every agent session — necessarily. But
config precedence is canonical-beats-legacy, so a fixture that configures
itself with `ARACHNE_TASKS_DIR=<tmpdir>` is silently outranked by the
session-level canonical spelling: the test reads the real ledger while
believing it reads its fixture. The 2026-08-13 G3 drain agent saw 64 spurious
failures across three suites and burned session time proving they were not
its own — the false-red mirror of the false-green problem
`TASKPUMP_NO_CONF=1` already solved for leaked conf files.

Build the environment half of that hermeticity:

- `tests/run-all.sh` scrubs the full `TASKPUMP_*` / `TP_*` / `ARACHNE_*`
  namespace at startup, before any suite runs (env-var enumeration, not a
  hand-kept list — `compgen -v` or `env | cut` over the three prefixes).
- Each suite does the same for standalone runs — the double-guard pattern
  `TASKPUMP_NO_CONF` already establishes. Suites that already clear
  CONTRACT_VARS per-case (test-entrypoint.sh) keep that; the startup scrub
  protects the fixtures built OUTSIDE run_ep-style wrappers.
- A suite that needs one of these variables sets it explicitly after the
  scrub; none may inherit it.

## Scope

`tests/run-all.sh` and each `tests/test-*.sh` prologue. No tool changes: the
pump's exports are correct, the suites' inheritance of them is the bug.

## Acceptance

- `TASKPUMP_TASKS_DIR=$PWD/tasks TP_TASKS_DIR=$PWD/tasks ./tests/run-all.sh`
  (the exact environment an in-container dogfooding agent gets) is green,
  with the same assertion count as a clean-env run.
- A control proves the guard: before the scrub lands, that invocation
  reproduces spurious failures; after, zero.
- run-all's existing repo-hermeticity check (issue #20) stays green — the
  scrub must not regress the litter guard.
