# G6.4 — The design notes and the example conf describe what shipped

## Spec

Two documents mislead a reader who does exactly what the project asks of them.
`docs/design/review-gates.md` reads as a live forward plan for a feature that
shipped, so a reader who lands there from a search concludes review gates are
unbuilt and goes looking for a template nobody wrote. `examples/arachne.conf`
ships with a citation on every pinned key — the one property that made it worth
shipping as an example — and the citations point at unrelated lines, so a reader
who checks one learns to stop checking.

Issues: **#58** (design-note banners and a missing template) and **#53**
(drifted citations in the reference conf). They are one task because they are
one pass over documentation that no code lane touches, which is what makes them
free concurrency in this wave. Every file:line below is a starting point for a
search, not a coordinate.

### #58 — the design notes

`docs/design/` is a directory of dated records. Some notes open with a
`> **Naming note (TaskPump extraction).**` banner telling the reader so; some do
not, and a reader has no way to tell which is which. `review-gates.md` is the
damaging one: it defers brief rendering and pump dispatch to future stages,
names `templates/review-brief.md` and `adjudicator-brief.md` as deliverables
(neither exists), and parenthesises issue #11 as "(still open)" when #11 and #12
are both closed and `--grain task` shipped with a 37 KB suite behind it. The
actual specification of the shipped surface is `docs/LEDGER-CONTRACT.md` §5.12,
which the reader never reaches.

What must be true after:

- `docs/design/review-gates.md` opens with a dated banner saying four things:
  this note produced the shipped review-gate feature; #11 and #12 are closed;
  the ledger surface (`review`, `verdict`, `review_role`, `review_of`, the fsck
  checks) is implemented and specified in `docs/LEDGER-CONTRACT.md` §5.12, which
  is what to read for current behaviour; and the "Extension points" section is
  still forward-looking — pump dispatch of review units, the two brief
  templates, and the monitor badges have **not** been built, and those two
  template files do not exist. Strike the "(still open)" parenthetical.
- `docs/design/dogfood-drain-sequence.md` and `docs/design/f90-addenda.md` each
  gain a one-line historical banner: written 2026-08-12 for the G-plan drain,
  kept as a dated record, not a manual.
- `docs/design/monitor-colour.md` already carries a naming banner. It is in this
  footprint so the banner convention can be made uniform and so the new
  assertion can be checked against it; change it only if the assertion's marker
  shape demands it.
- Bodies otherwise unchanged. These are dated records; a path that no longer
  exists inside a note marked historical is a record of what was planned, not a
  broken reference. That is precisely what the banner buys, and it is why the
  four dead paths in `docs/design/` are covered by banners rather than edited.
- `templates/review-brief.md` is declared in this footprint so you have the
  option, not the obligation. The issue's recommendation, and the cheaper
  correct answer, is to **state in the banner that the file does not exist**
  rather than to write a template nothing renders. If you create it instead,
  it must be a real template the shipped code path can render, and you must say
  in the completion note why you chose the larger option.

Note a discrepancy the issue predates: `docs/design/` now holds **seven** notes,
not six. `docs/design/session-fanout-protocol.md` also lacks a banner and is
**not** in this task's declared files. See Scope.

### #53 — the reference conf's citations

`examples/arachne.conf` pins keys with `# (pin; shipped default: X — tool:NNN)`.
The numbers drifted wholesale across releases and were never re-derived, so
following one lands on an unrelated line — a comment about something else, or a
bare `fi`. The drift is uniform enough (roughly +90 lines in `tp-pump`, −18 in
`tp-task`) that a reader may conclude one row is wrong rather than the file.

Do **not** hand-patch the numbers. That is exactly how they got here. Replace
the `:LINE` half of every citation with the **symbol**, e.g.
`# (pin; shipped default: tp-task — libexec/tp-task, TASKPUMP_PROG_NAME)`. A
file-plus-symbol citation is as checkable as a line number — one `rg` finds it —
and it cannot go stale under an unrelated edit.

Re-derive the count yourself. The issue says 50 rows with 49 misses; at the time
this task was written `grep -cE '(tp-pump|tp-task|tp-monitor|pump-lib\.sh|entrypoint\.sh):[0-9]+' examples/arachne.conf`
returns **53**, against 57 `KEY=` rows. Trust the grep, not the prose.

While editing, **re-verify each row's stated default value** against the cited
symbol's site. The line numbers drifted because nobody checked them; nobody has
checked the values either, and a wrong default in the reference conf is worse
than a wrong citation.

`examples/minimal.conf` carries no line citations. It is in this footprint so
the new assertion can be run against every `examples/*.conf`, and so that if the
sweep finds a citation there it can be repaired in the same pass.

## Scope

Declared footprint: the four design notes named above, `templates/review-brief.md`,
`examples/arachne.conf`, `examples/minimal.conf`, `tests/test-example-confs.sh`.
Nothing enforces that list but you, and this task was scheduled beside three
code lanes on the promise that a documentation pass touches no code.

Out of scope:

- **`docs/design/session-fanout-protocol.md`.** It also lacks a banner and it is
  not in your files. Do not edit it. Write the assertion so it fails honestly
  and record the file in your completion note as the one remaining banner, owned
  by **G6.13** (the phase's doc tail) — or, if you scope the assertion to the
  notes this task owns, say so explicitly in the completion note and name the
  gap. Do not paper over it by weakening the assertion silently.
- `README.md`, `docs/RUNBOOK.md` and `tests/test-docs-claims.sh` — **G6.11**. The
  docs suite the issue imagines lives there; the only test file you own is
  `tests/test-example-confs.sh`, so both new assertions go in it. Name them to
  the house convention anyway, and record in the completion note that the
  banner assertion is housed in the conf suite for footprint reasons.
- `docs/LEDGER-CONTRACT.md`, `docs/CONFIG.md`, `taskpump.conf.example`,
  `CHANGELOG.md`, `VERSION` — **G6.13**.
- The three correct line citations elsewhere (`docs/CONFIG.md`,
  `docs/GATES.md`, `README.md`) verify correct today. Leave them alone; they are
  not yours and they are not wrong.
- Any tool change the pass reveals as needed becomes a note in the completion
  note, not an edit. This is prose.
