# G0.2 — Complete the dogfood launch configuration

## Spec

The dry-run plans correctly, but a *real* launch on this repository would fail
on four Arachne-shaped launch-path defaults. Set each explicitly in
`taskpump.conf` and validate with one supervised tick:

1. **Ledger repo** — `OPS_DIR` defaults to `$REPO_ROOT/ops` (`tp-pump:81`),
   which does not exist here: every tick's ledger fast-forward warns, and the
   runner would mount a nonexistent path as `TP_LEDGER_REPO`. Set
   `TASKPUMP_LEDGER_REPO=.` — the ledger lives in this repository. Consequence
   to validate and document in the conf comments: the primary checkout is then
   the RW ledger mount, so the read-only-primary hardening does not apply to
   the dogfood repo; ledger commits are atomic so fs-guard should stay clean.
2. **Task CLI** — briefs and the entrypoint default to `scripts/arachne-task`,
   which does not exist here. Set `TASKPUMP_TASK_CLI=bin/tp` and
   `TASKPUMP_WORKSPACE_TASK_CLI=bin/tp` (this repo vendors its own CLI by
   definition).
3. **Image + entrypoint** — no TaskPump agent image exists. Author a minimal
   `runners/claude-docker/Dockerfile` (bash, git, mikefarah yq v4, jq, gawk,
   the claude CLI, the runner's `entrypoint.sh` baked at the path
   `TASKPUMP_ENTRYPOINT` names) — this also becomes the concrete image
   contract G1.5 documents. Set `TASKPUMP_IMAGE=taskpump-agent`. Riding the
   `arachne` image with `/entrypoint-parallel.sh` is the fallback if the
   Dockerfile stalls, and pins for that path go in the conf commented out.
4. **Concurrency** — `TASKPUMP_JOBS=1` until a full supervised drain of one
   phase has been watched.

## Scope

`taskpump.conf`, the new Dockerfile, and the supervised validation tick. No
tool changes — anything the tick exposes in the tools becomes its own task
(as G0.1 was).

## Acceptance

- `tp pump --phases G1 --dry-run` shows the resolved image, task CLI, and
  ledger repo with no warning about `ops`.
- A supervised `tp pump --phases G1 --once --jobs 1` launches a real agent
  that claims G1.1, heartbeats, and either completes or releases it, with the
  ledger state visible from the primary afterward (`tp task list` reflects the
  agent's work; `git -C . log tasks/` shows the agent's commits).
- `tp monitor` during that tick shows the session and the G-phase DAG.
- The conf documents every pin with one line of why, in the arachne.conf
  style.
