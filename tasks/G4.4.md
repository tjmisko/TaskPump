# G4.4 — Write the bring-your-own-repo adoption walkthrough

## Spec

The document that makes adoption real: a walkthrough taking an existing
repository from nothing to a first supervised drain.

- README gains an "Adopt in an existing repo" section: `tp init`; author tasks
  (`tp task create`) or import an existing markdown task directory
  (`tp task fsck --fix`); inspect the frontier; `tp pump --dry-run`; one
  supervised `--once`; then `--jobs 1` with the monitor open.
- The runner decision is presented honestly: claude-docker (sandboxed, needs an
  image) vs runners/local (no sandbox, no docker) — one paragraph each, with
  the local runner's permissions caveat repeated.
- docs/CONFIG.md's discovery section links the walkthrough; the walkthrough
  never mentions Arachne — the Provenance section is where that story lives.

## Scope

Prose and the CI hook below. No tool changes; anything the walkthrough reveals
as missing becomes a new task.

## Acceptance

- Every command in the walkthrough runs verbatim in a scratch repo (the
  generic-consumer CI smoke extends to cover the init → create → ready →
  dry-run path).
- `rg -n 'arachne' <the new sections>` is empty.
- A reader following only the walkthrough ends with a running `--once` tick
  using the local runner and a stub agent command.
