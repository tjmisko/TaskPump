# G10.4 — The exit-code conformance matrix

## Spec

§10 of `docs/LEDGER-CONTRACT.md` calls the exit codes "a wire protocol between
processes" and freezes them. Until now the protocol has been checked the way
prose is checked: by reading it. That is how the tree arrived at a frozen table
whose 2 row no tool honoured (#71) and whose 0 row was false for seven of eight
pump invocations (#72), with a conformance note that grew to explain the gap
rather than close it. G10.1 and G10.3 closed both. This task makes closure a
standing property instead of a claim: a table-driven suite that drives every row
of §10, for every tool, in both directions.

**Both directions is the whole design.** A one-directional suite — "the documented
invocation produces the documented code" — passes on a tree where every command
exits 2, which is exactly the wrong fix somebody will reach for. So each row is
asserted twice: the invocation that documents the code produces it, **and** no
other invocation in the table produces it.

### The rows

Drive every code §10 names, not a subset:

- **0** — success; for the pump specifically, a loop drain, with the G10.1 rule
  that a drain is `status == "drained" && mode == "loop"` in the state file. The
  other seven exit-0 pump invocations belong in the table as rows that produce 0
  **and are not drains**, because that pairing is the defect #72 was.
- **1** — `tp task next` on an empty frontier; `tp task scrub` failing to run;
  every operational failure, including `tp pump --phases X` with no `tasks/`
  directory. Explicitly asserted as *not* 2 after G10.3.
- **2** — bad CLI arguments, for every tool `bin/tp` dispatches, in the three
  shapes G10.3 landed: unknown verb, unknown flag, flag with its value omitted.
  Plus the runner-capability meaning §10.2 records — `runners/local/runner.sh`
  and `runners/claude-docker/runner.sh` answering 2 for a verb they do not
  implement — asserted as a distinct row so the two meanings of 2 stay legible.
- **3** — `tp task scrub` with an unparseable/no-id task file; `tp task fsck` with
  a contract violation; `tp pump` deadlock, in each of the shapes G10.1 made
  reachable (empty plan, every-launch-fails, cap-0 excluded, all-dead-end range).
- **10** — a gate pausing, and `tp task resume-attempt` with its budget spent.
  The plan's acceptance listed 0/1/2/3/75; 10 is a row of §10 and belongs here,
  and asserting it costs one fixture.
- **75** — the reference runner's entrypoint signalling `EX_TEMPFAIL` before any
  claim. Assert it and assert the property that makes it worth having: no failed
  iteration is recorded against any task.

Read the table out of `docs/LEDGER-CONTRACT.md` where you can rather than
transcribing it, so a future row added to the contract without a test fails the
suite instead of passing unnoticed.

### Hermeticity and honesty

`tests/run-all.sh` discovers `tests/test-*.sh` by glob, so registration is
automatic; your declared edit to it is for the hermeticity manifest and for
whatever the new suite needs declared there, not for a suite list. Source
`tests/suite-prologue.sh`, work in `mktemp -d`, and leave the repo tree and its
run-state files untouched — `run-all.sh` fails the run if you do not.

A conformance suite that silently skips rows is worse than no suite, because it
reports green over the thing it was built to find. Print an assertion count and
fail if any row of the table went undriven.

### The doc and release debt this task lands

G10.1 and G10.3 each recorded a migration note in their completion notes. This
task is the phase tail and owns `CHANGELOG.md`, so both land here, verbatim:

- exit 2 for bad arguments in `tp task` / `tp pump` and the peripheral tools (#71),
- the state file's `mode` / `invocation_id` fields and `--detach`'s `handed-off`
  status (#72),

and alongside them the two consumer-visible behaviour changes that need a note
even though no code moves: `--grain phase` now treating a blocker with no branch
as integrated (#75, with its `TASKPUMP_PUMP_INTEGRATION_REQUIRE_BRANCH=1`
opt-out), and exit 3 now being produced where 0 was produced before (#112/#131),
which a `Restart=on-failure` supervisor will notice.

`docs/LEDGER-CONTRACT.md` §10.1 records the closures. Some G10 doc debt falls
**outside** your `files:` — the new integration key belongs in `docs/CONFIG.md`
and `taskpump.conf.example`. Do not reach for them. Forward them explicitly in
your completion note: `docs/CONFIG.md` → G11.3, `taskpump.conf.example` and
`README.md` → G11.4. A forwarded item that names its owner gets landed; one that
says "docs need updating" does not.

## Scope

Four paths: the new suite, `tests/run-all.sh`, `docs/LEDGER-CONTRACT.md` and
`CHANGELOG.md`. Nothing enforces that but you.

The suite **executes** tools, runners and the entrypoint; that is not the same as
owning them. If a row fails, the fix is in the tool and the tool is not yours —
`libexec/` and `bin/` belong to G10.1 and G10.3, which have landed by the time you
run. Reopen or file, do not patch. The one exception a reviewer will accept is a
fix inside your own suite's fixtures.

`VERSION` is not yours: this phase does not cut a tag. v0.3.0 ships at G11.4.
