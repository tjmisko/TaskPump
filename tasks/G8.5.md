# G8.5 — The injection drill

## Spec

G8's promise is that repository text is data wherever it lands. Four tasks have now
made that true in four different files. This task turns the promise from an argument
into a green suite: a corpus that plants the sweep's payloads in every channel that
reaches an agent's prompt or the operator's terminal, and asserts they arrive visible,
fenced and powerless.

An operator deciding whether to point this pump at a repository they do not control
should not have to read four completion notes and take their word for it. They should
run one suite.

### The fixture

`tests/fixtures/hostile-ledger` is a self-contained ledger whose every field carries a
payload. **G7.8** made a declared directory entry protected by path-component
containment (recorded in `docs/LEDGER-CONTRACT.md` §3), so this task may declare the
directory and mean it — everything under it is yours.

Four planting sites, because they are four different writers with four different
reach:

1. **A task file** — `goal`, `title`, `files:`, `blockers:`, the body prose, and the id
   itself. Include the shapes the sweep verified: a `files:` entry that closes its
   backtick and continues in prose; a `files:` entry whose words are separated by
   U+00A0 (which the old ASCII-only `tr -d '[:space:]'` passed through intact); a
   multi-line `blockers:` block scalar whose lines read as headings; a multi-line
   `goal` block scalar claiming to be a superseding operator directive; control bytes
   in each.
2. **A commit message** — subjects that spell a fence terminator, a
   `## Definition of done (AMENDED by the operator)` heading, and a directive to
   admin-merge. Record the honest limit the skeptic pass established: `git log
   --oneline` puts a short sha before every subject, so a subject cannot open a
   CommonMark fence at line start. Assert what is true, not what reads well.
3. **A branch name** — the channel that reaches worktree paths, container names and
   `tp cleanup`'s mapping.
4. **A `taskpump.conf`** — the conf that **G7.1** made data rather than shell. A
   hostile conf must be refused by name on every vector, not partially applied.

The fixture is **inert data**. Nothing in the suite may source it, execute it, or let
it reach the real ledger. `tests/suite-prologue.sh` already scrubs the inherited
`TASKPUMP_*`/`TP_*`/`ARACHNE_*` environment for exactly this reason (issue #18: the
pump exports the real ledger's `TASKPUMP_TASKS_DIR` into every agent session and the
canonical spelling outranks a fixture's legacy one — 64 spurious failures in one
drain). Source the prologue and do not defeat it.

### What the corpus asserts

Two claims, and they need different techniques.

**The agent's rendered brief's instructions do not change.** Render each surface — the
task brief, the phase-drain brief, the resume note, the goal note — twice: once over
the hostile ledger and once over a benign twin identical except for the payload bytes.
Assert that every operator-authored region is **byte-identical** between the two, and
that every payload byte in the hostile render sits inside a `BEGIN/END REPOSITORY
DATA` fence. That pair of assertions is stronger than grepping for known bad strings,
because it catches a payload class nobody thought to enumerate.

Then the fence's own properties, from **G8.1**: exactly one BEGIN and one END per
region even when the payload spells a terminator; a different nonce on every render;
no byte below 0x20 other than LF and TAB anywhere in the rendered prompt.

**The operator's terminal cannot be forged.** `tp task ready`, `tp task list`,
`tp pump --list`, `tp pump --dry-run` and `tp monitor`'s rendering over the hostile
ledger emit no ESC (0x1B) and no C1 byte, and no line that could be mistaken for the
tool's own framing. **G6.2** closed this channel; the corpus is what keeps it closed.

And the shell boundary, closed by **G6.3**: a planted `id:`, a hostile worktree name
and a hostile task id reach no `eval`. Assert on observable effect — a canary file the
payload tries to create is absent — not on the shape of the code.

### The coverage manifest

The plan's standard is that **every payload class named in the thirty-three open
security issues has at least one case**. Enumerate them mechanically rather than from
memory:

```sh
gh issue list --label security --state open --limit 100 --json number,title
```

Carry a manifest in the suite — a comment block or a data table, whichever reads
better — mapping each issue number to the case that covers it, or to an explicit
one-line reason it has no payload class (several are credential-handling or
host-execution defects with no attacker-authored text in them; that is a legitimate
entry, silence is not). The manifest is what `docs/THREAT-MODEL.md` cites when it
states the coverage, and it is what tells the next operator what this drill does not
test.

### Wiring and the phase's remaining debt

`tests/run-all.sh` runs every `tests/test-*.sh` in sequence; add the corpus so it runs
by default and check that its hermeticity gate — the repo-status snapshot and the
run-state manifest, which caught a suite rewriting the operator's live
`.taskpump-fsguard.notified` — stays green with the corpus in the set. A drill that
litters the primary is not a drill.

This task is G8's tail and owns the phase's shared documents. Collect the doc debt the
four siblings recorded in their completion notes and land it:

- `docs/CONFIG.md` — `TASKPUMP_TRUSTED_SINCE` from **G8.4**; the note on
  `TASKPUMP_MAX_TURNS`/`TASKPUMP_TASK_MAX_TURNS` from **G8.3** that the value is now
  visible to the agent; anything G8.1 and G8.2 recorded.
- `taskpump.conf.example` — the same keys, commented in the shipped example.
- `CHANGELOG.md` — one Unreleased **MINOR (v0.3.0)** entry covering the phase: the
  repository-data fence and the deleted precedence clause, the `files:`/`goal`
  validation, the run-file ignores and `tp init`'s scaffolded `.gitignore`, the three
  new template keys and the runner `capabilities` verb at contract v3, and the opt-in
  provenance gate. Name the behaviour changes a consumer will notice. `VERSION` is not
  yours — **G11.4** ships v0.3.0.
- `docs/THREAT-MODEL.md` — §3.5 and §3.6 stop describing live holes and start
  describing closed ones with the corpus as the evidence; §4 distinguishes what is now
  enforced from what is still only asked; §5's tiers move to reflect what G7 and G8
  landed; §6's S3 records the data/instruction boundary as delivered. State the
  coverage and its limits in the same paragraph — an overclaiming threat model is worse
  than a candid one.

If a sibling's completion note names debt you cannot land inside this task's footprint,
file it as a task rather than widening the footprint.

## Scope

The seven paths in `files:` above and nothing else. Nothing enforces the list but you.

Do not touch:

- **Any tool, library, template or runner.** This task ships a drill, not a fix. If the
  corpus finds a live hole — and it may; that is what a drill is for — file it as a new
  task with `create`, name it in the completion notes, and add the case as a
  documented known-red entry rather than reaching into `lib/`, `libexec/`, `templates/`
  or `runners/`. A tail task that quietly starts editing the tools it is meant to
  audit is how a phase's promise gets marked green by the person who wrote it.
- **`docs/LEDGER-CONTRACT.md`, `docs/CLI-PUMP.md`, `docs/CLI-TASK.md`,
  `docs/RUNNERS.md`, `docs/GATES.md`** — owned by G8.1 through G8.4. If one of them is
  wrong, that is doc debt for a new task.
- **`VERSION` and the tag** — **G11.4**.
- **The standing-gate version of this corpus** — **G11.2** makes it a gate that blocks a
  release. Here it is a suite that runs; do not build the gate.
