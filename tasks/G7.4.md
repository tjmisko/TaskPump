# G7.4 — The container holds only the token it needs

## Spec

Every agent the pump launches is handed the operator's entire `~/.claude` directory and
`~/.claude.json`. On the machine the sweep measured, that is 1.2 GB of complete transcripts
across 39 unrelated projects, a 2.5 MB `history.jsonl` of every prompt the operator has
ever typed, `paste-cache/`, `file-history/`, `backups/`, `debug/`, a live OAuth access
token, and a `.claude.json` whose schema carries `mcpServers` with their `env` blocks —
which is where MCP API keys live. The exposure is unconditional. It happens on every launch
whether or not anything goes wrong.

This task is not one of the five reasons the plan's `safe_to_self_drain_after` gives for
withholding unattended operation, but it sets the ceiling on what any of those four
failures costs. An agent that reads an instruction it should not obey has `Bash(cat:*)`
pre-approved and two egress channels still open (DNS, and a GitHub push or PR body). What
it can carry out is decided here. G7.5 blocks on you for the entrypoint, and G7.9's drill
runs against the boundary you land.

This task blocks on **G6.13**, the v0.2.2 tag, and that blocker is load-bearing rather than
ceremonial. A task-grain range run plans every phase in range in one tick, so without the
barrier the scheduler would dispatch this MINOR mount change beside the patch line and it
would ship inside a PATCH tag.

Two issues, one mount block. Line citations below are from the 2026-08-19 sweep and have
already moved once. Search by name.

### #81 — the whole agent home is mounted and copied

`runners/claude-docker/runner.sh` mounts `-v "$claude_dir":/tmp/claude-home:ro` and
`-v "$claude_json":/tmp/claude-home-json/.claude.json:ro`, with `claude_dir` defaulting to
`$HOME/.claude`. `runners/claude-docker/entrypoint.sh` then does
`cp -a "$HOST_CRED_MOUNT"/. "$AGENT_CLAUDE_DIR"/` and chowns and `chmod -R u+rw`s the copy
to `CONTAINER_USER`. The only narrowing anywhere is `install_access_only_credentials`,
which is exactly `jq 'del(.claudeAiOauth.refreshToken)'` — the access token is deliberately
kept.

After this task:

- The runner mounts **no directory** from `$claude_dir`. Only named files, mounted
  individually.
- `install_credentials` copies from an explicit allowlist of file names rather than
  `cp -a …/.`, and logs by name anything present in the mount that the allowlist does not
  cover. After the install, `$AGENT_CLAUDE_DIR` contains no `projects/`, no
  `history.jsonl`, no `paste-cache/`, no `file-history/`, no `backups/`, no `debug/`.
- `~/.claude.json` is projected through `jq` rather than mounted: drop `mcpServers`,
  `oauthAccount` and `projects`.
- A session still authenticates and runs. The access-token path is unbroken; this is a
  scope change, not a de-authentication.

### #126 — the unstripped host credential file stays mounted for the life of the container

Stripping the refresh token out of the *copy* does not help while the *unstripped* host
file is bind-mounted at `/tmp/claude-home/.credentials.json`, one `cat` away, for the whole
run. It has to stay mounted, by construction: the background refresher re-reads it every
`CRED_REFRESH_INTERVAL_S` (default 300) from a loop the entrypoint starts.

Whether the agent can read it comes down to one thing nothing pins: whether the container's
unprivileged user has the same numeric uid as the host operator. Bind mounts preserve
numeric uid, the host file is mode `0600`, its directory is world-traversable, so the
`0600` bit is the entire control and it is a *uid* barrier. The runner deliberately passes
no `--user`; the entrypoint drops to `TASKPUMP_CONTAINER_USER` (default `dev`) with
`setpriv` and never asserts a uid; and TaskPump ships no image — `docs/RUNNERS.md` says
"TaskPump ships the runner, not the image", and the §4.0 image contract lists the `claude`
CLI, `git`, `jq`, `setpriv`, `bash` 4+, `yq` v4, `gawk` and "an unprivileged user to drop
to", with no uid requirement at all. On any Debian- or Ubuntu-based image whose first
non-root user is uid 1000 — the overwhelming default, and what a consumer following the
contract will build — `dev` is uid 1000, matches the operator running the pump, and reads
the mounted host credentials for the whole run.

Note that #81's own proposed fix explicitly *keeps* this mount
(`-v "$claude_dir/.credentials.json":/tmp/claude-home/.credentials.json:ro`) and its
acceptance criteria are satisfied while the unstripped file remains readable. That is
precisely why the two issues are one task: doing #81 without #126 leaves the file the agent
must not have sitting in the agent's filesystem, and doing them in separate passes means
the second rewrites the first's mount block.

Take fix **(1)**, the real one: write a stripped, access-token-only **projection** of the
host credentials to a mode-`0600` host path owned by the operator, and mount **that** at
`/tmp/claude-home/.credentials.json:ro`. The refresher then re-reads a file that never
carried a refresh token, and the strip happens once, on the host, where a failure can abort
the launch instead of being logged and swallowed. The projection must be refreshed on the
host side so the container still tracks host token rotation within one
`CRED_REFRESH_INTERVAL_S`.

Fix **(2)** — the uid assertion before the privilege drop, comparing `id -u
"$CONTAINER_USER"` against the owner uid of the mounted credential file and exiting 75 —
is worth having as a belt-and-braces check even under (1), and its diagnostic must name the
remedy. Exit 75 is already the entrypoint's operator-recoverable startup code, so no
reserved code moves.
