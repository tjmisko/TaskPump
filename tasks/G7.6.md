# G7.6 — A review cannot be signed by the branch under review, and a hand-edit cannot ride in on a verb's commit

## Spec

Two of the five vectors G7.9's unattended-safety drill fires are yours: a self-approved
review, and a forged ledger mutation laundered into a signed commit. The operator does not
walk away until that drill is green against real refusals, so "reported somewhere" is not
sufficient for either half — both must be refusals or contract violations with an exit
code.

G7.2 landed the claimant checks and the actor in the commit trail; G7.5 landed the budget
and the heartbeat claimant. You are the third pass over `libexec/tp-task` and G7.8 is the
fourth. Line citations below are from the 2026-08-19 sweep and have already moved twice; at
the time of writing `git_commit_state` is at `libexec/tp-task:342`, `cmd_verdict` at
`:1708` and `cmd_fsck` at `:2639`. Search by name.

### #84 — the implementer can close its own review gate

A review gate exists so that work is scrutinised by someone other than its author. In
TaskPump the implementer can close its own. The pump never dispatches a review unit — it
says so in its own source — so once an agent completes a task, the only actors who can
render a verdict are a human or the implementing agent that is still running and whose
downstream is now blocked. That agent runs two commands:
`tp task claim <gate> --branch <its own branch>`, accepted because `claim` checks the
task's status and never the caller's other holdings, and
`tp task verdict <gate> --approve --branch <same branch>`, accepted because the ownership
check compares the caller-supplied `--branch` to `claimed_by` and nothing else. Simpler
still, it can skip the claim: a verdict on an *unclaimed* gate with no `--branch` at all
emits a warning and proceeds. Both paths ran green on the swept revision, and the skeptic
pass reproduced both independently.

The ledger then holds a rendered adversarial-review approval of work the reviewer wrote,
indistinguishable from a real one — what `docs/design/review-gates.md` calls the one shape
of review that is worse than none, because it looks like independent scrutiny. The file
states the consequence in its own source: the self-review exclusion is "advisory" because
it is a frontier query skip, not an eligibility predicate.

After this task:

1. `cmd_claim` refuses a claim on a review task whose `review_of` subject was claimed or
   completed by the calling branch. The chain already records `review_of`, so it is one
   `fm_get` plus one comparison against the subject's `claimed_by` and the actor field G7.2
   added.
2. `cmd_verdict` refuses when the caller's branch equals the subject's implementing branch,
   **independently of who holds the gate**. Belt and braces: the claim check alone can be
   evaded by claiming under a different branch name.
3. The unclaimed-gate warning becomes a **refusal** unless an explicit operator flag is
   present (`--as-human`, or `TASKPUMP_OPERATOR=1`). §5.12's rounds-exhausted door is a
   human path and a human can pass a flag.

Deliberately unchanged: a phase sitting on an unrendered gate remains a stall. That is the
correct loud behaviour by `docs/design/review-gates.md`'s own argument and it must not be
relieved by a self-verdict. An independent reviewer branch must still claim and rule
normally — assert that, because it is the path the change risks breaking.

### #85 — `git add -A` launders a hand-edit into the next verb's commit

The brief's last boundary is that `tp task` is the sole writer of task state and nobody
hand-edits frontmatter. Nothing enforces it. The ledger checkout is mounted read-write in
every runner, so an agent can write the YAML directly — clear another task's blockers, set
its status to `done`, reset its own budget — and the eligibility frontier changes with no
verb involved. Then the CLI finishes the job: `git_commit_state` stages with
`git -C "$tasks_git_root" add -A -- "$TASKPUMP_TASKS_DIR"`, so the very next ordinary verb
sweeps the hand-edit into a ledger commit under the CLI's committer identity and, with
`TASKPUMP_TASK_PUSH=1` (which the entrypoint exports), pushes it to the shared remote where
every sibling and the monitor read it as authoritative. `fsck` exits 0, because it is a
schema conformance check, not a provenance check.

The reproduction to close: hand-edit `T3.0` to `done` and `T3.1`'s blockers to `[]` by raw
file write, then run an unrelated legitimate `tp task create T3.2` — the commit titled
`create T3.2` carries all three files and `fsck` returns 0.

After this task:

- **Staging is narrowed.** `git_commit_state` stages only the task file or files the verb
  actually wrote (`git add -- "$file"`), never the directory. An unrelated dirty task file
  stays dirty instead of being laundered, which by itself makes hand-edits visible and
  persistent. The existing scoping to `$TASKPUMP_TASKS_DIR` shows the intent; it is simply
  not narrow enough.
- **Drift is detected and named.** Before staging, diff the tasks directory and report any
  modification the verb did not make. Add an `fsck --drift` mode that diffs working-tree
  frontmatter against the last committed state, names every file changed outside a verb,
  and exits **3** — the code `docs/LEDGER-CONTRACT.md` §10 already reserves for "≥1 contract
  violation in the ledger, actionable, not a crash", which is exactly what this is. Do not
  invent a new exit code.

The pump's pre-tick preflight should stop the drain on a drifted ledger. That wiring lives
in `libexec/tp-pump`, which is **not yours** — see Scope.

## Scope

to **G7.8**, which owns `libexec/tp-pump` and blocks on you: state in your completion note

record the pre-tick documentation as debt.

You must **not** touch `cmd_create`'s or `cmd_fsck`'s `files:` grammar handling — that is
**G7.8**. Keep `fsck --drift` a separate mode so the two changes do not collide.

Keep the new mode additive in `cmd_fsck`: `tests/test-tp-task-fsck.sh` is not in your
footprint, so if that suite goes red you have changed default `fsck` behaviour and the
answer is to narrow the change, not to edit the suite. Put every new drift assertion in
`tests/test-tp-task.sh`.

`CHANGELOG.md` belongs to **G7.9**. Record the debt: a new flag and a new mode appear, a
§5.12 transition becomes conditioned on the actor, and a verb that previously committed a
