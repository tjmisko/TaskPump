# G11.4 — v0.3.0 ships with its migration notes

## Spec

This is the tail of the range. Every fix is in, every drill is green, and what is
left is the part a consumer actually receives: a version, a changelog that names
what changed, and — the part releases usually get wrong — a migration note for
each change an integrator has to act on. A behaviour change shipped without a note
is indistinguishable, from outside, from a bug.

Follow this repository's own release precedent, recorded in `tasks/G2.3.md` and
its completion note: bump `VERSION`, turn CHANGELOG's `Unreleased` heading into
the version with its date, cut an annotated tag on the release commit, push the
branch and the tag. Do not invent a different process, and do not tag before the
suite is green on the exact tree being tagged.

### The changelog, in two registers

**One:** every issue closed since v0.2.2 is named. The tracker's v0.3.0 milestone
carried 45 open issues when this plan was written — confirm the number rather than
copying it (`gh issue list --milestone v0.3.0 --state all`), and reconcile against
what actually landed. An issue in the milestone that no commit in the range closed
is a discrepancy to state plainly in the release notes, not to quietly drop.

**Two, separately and above the issue list:** the behaviour changes an integrator
must act on. Each of these has a migration note already drafted by the task that
landed it — lift them verbatim from those completion notes and from
`docs/LEDGER-CONTRACT.md` §10.1 rather than paraphrasing:

- **conf parsing** (#77) — a `taskpump.conf` is no longer sourced as shell;
  constructs that used to work are now refused by name.
- **claimant checks** (#83, #90, and the durable half in #84/#130/#85) — a
  mutation from a branch that does not hold the claim is refused.
- **the build-gate default** (#79, #117) — repo-supplied `smoke_test.sh` and
  `cargo` no longer run on the host by default; a consumer relying on them must
  opt back in.
- **gate-chain refusal** (#122) — a gate that cannot run refuses instead of
  reporting `GATE: feed-ok`.
- **the footprint grammar** (#91) — declared paths are compared by containment, so
  a pair that used to co-schedule may now be held.
- **exit 2** (#71) — `tp task` and `tp pump` return 2 for bad arguments; a script
  testing `[[ $? -eq 1 ]]` must change.
- **the state file's invocation field** (#72) — `mode` and `invocation_id` are
  added, `--detach` stamps `handed-off`, and a drain is
  `status == "drained" && mode == "loop"`.
- **the phase-grain integration default** (#75) — a cross-phase blocker whose
  branch does not exist now counts as integrated;
  `TASKPUMP_PUMP_INTEGRATION_REQUIRE_BRANCH=1` restores the old strictness. The
  plan's own acceptance list omits this one; it is consumer-visible, it has an
  opt-out key, and it ships with a note like the rest.

### The other three files

- **`docs/LEDGER-CONTRACT.md`** — §10.1 and §10.2 record the closures as of
  v0.3.0, keeping the v0.2.x statements clearly marked as history for readers who
  cannot upgrade. The frozen table in §10 is **byte-unchanged**; if anything in
  this range needed it to change, that was a MAJOR and it did not happen. §1's
  versioning rules are what justify calling this MINOR — check the release against
  them and say so in the release notes.
- **`taskpump.conf.example`** — carries every key the tools now read, including
  the ones forwarded to this task as debt (`TASKPUMP_PUMP_INTEGRATION_REQUIRE_BRANCH`
  from G10.1 via G10.4, plus whatever G11.3's census delta names). G11.3 asserted
  the census against `docs/CONFIG.md`; this file must agree with it.
- **`README.md`** — the version and any claim the range falsified. Read G11.3's
  completion note first: it just ran every README command in a scratch repo, and
  anything it could not fix inside its own footprint is addressed to you.

### Before the tag

The full suite must be green **on the tagged tree**, including every drill this
range built: G6.12's hostile ledger, G7.9's unattended-safety drill, G8.5's
injection replay, G9.6's foreign-consumer drain, G10.4's exit-code conformance
matrix, and G11.1's and G11.2's CI-hosted successors. Green on a branch that later
merged is not the same claim. Record the run and the commit sha in the completion
note the way G2.3 did.

## Scope

Five paths: `VERSION`, `CHANGELOG.md`, `docs/LEDGER-CONTRACT.md`, `README.md`,
`taskpump.conf.example`. Nothing enforces that but you.

This task is the phase tail and owns `VERSION` and `CHANGELOG.md` alone, by the
same rule G2.3 established — a release file with two writers produces a version
that disagrees with its own changelog. Its three blockers have landed by the time
it runs, so nothing else in the plan is holding these files.

Ship no code. If the release preparation exposes a defect, it does not get fixed
here: file it, target it at the next milestone, and say in the release notes
whether it is a known issue for v0.3.0. A last-minute fix in a release commit is
untested by construction, because the suite you are about to certify ran before it.
