# G7.2 — A ledger verb refuses a caller that does not hold the task

## Spec

The ledger is what the pump and every agent trust to decide who is working on what and
what is finished. Its mutating verbs authenticate nobody. Any agent can mark a sibling's
live task done — nulling the real holder's claim, recording commits that do not exist, and
releasing everything blocked behind it on the next tick — and the git history cannot say
who did it, because every mutation commits under one synthetic identity.

This is the base of the phase's second chain. G7.5, G7.6 and G7.8 all rewrite
`libexec/tp-task` after you and all three build on the claimant check you land here;
G7.9's forged-ledger drill is the executable form of this task's promise, and the operator
does not walk away until that drill is green. Do not leave the check half-built.

This task blocks on **G6.13**, the v0.2.2 tag, and that blocker is load-bearing rather
than ceremonial. A task-grain range run plans every phase in range in one tick, so without
the barrier the scheduler would dispatch this MINOR change beside the patch line and it
would ship inside a PATCH tag.

Two issues, one file. Line citations below are from the 2026-08-19 sweep and have already
moved once; at the time of writing the functions are at `libexec/tp-task:342`
(`git_commit_state`), `:869` (`cmd_claim`), `:1077` (`cmd_complete`), `:1146`
(`cmd_block`), `:1202` (`cmd_release`), `:1250` (`cmd_reopen`) and `:2833`
(`cmd_blockers`). Search by function name; treat the numbers as a starting point.

### #83 — the mutating verbs read no claimant, and the log records no actor

`cmd_complete` reads `.review_role` and nothing else about the caller. `cmd_block`,
`cmd_reopen` and `cmd_blockers` read nothing at all. The contrast is one screen away:
`cmd_verdict` *does* read `.claimed_by`, so the omission is not house style. Reproduced
against a real ledger: an agent on `feat/g1-1` completed `T1.2` held by `feat/g1-2` at
rc=0, the downstream blocked task became eligible, a sibling was blocked at rc=0, and a
completed sibling was reopened with its `completed_by_commits` erased.

`cmd_claim` has exactly three clauses — refresh when same-branch, refuse when not open,
refuse when claimed elsewhere. There is no clause counting the caller's existing claims,
and `--branch` is an unverified caller-supplied string. So one branch claimed all three
siblings in its phase at rc=0, and a claim for `feat/nobody` froze a task for everyone
else. Two corrections from the skeptic pass sharpen what the harm is: a claimed sibling
drops out of the frontier, so this is footprint bypass plus starvation rather than double
dispatch, and a squat under the task's *own* owner-branch spelling is auto-released by the
pump's `reclaim_orphaned_claims` — it is the *foreign* branch name that evades recovery.

Every mutation commits as `tp-task <task@taskpump.local>` and only `claim` puts a branch in
the message, so a forged `block` is byte-identical in form to a legitimate one.
`docs/LEDGER-CONTRACT.md` promises `git log` over the tasks directory is "a complete audit
trail of who claimed what, when, and how it ended". The "how it ended" half records no
actor at all.

After this task:

1. **Claimant check on the closing verbs.** `cmd_complete`, `cmd_block` and `cmd_release`
   refuse when the acting branch does not match `claimed_by`, in the wording `cmd_verdict`
   already uses, leaving `status` and `claimed_by` untouched and naming the holder.
2. **The acting branch is derived, not merely accepted.** When `--branch` is absent,
   discover it with `git -C "$TASKPUMP_CODE_REPO" branch --show-current`; when `--branch`
   is present and a real branch is discoverable, refuse a mismatch rather than trusting
   the argument. That is the half that closes the squat, and deriving rather than
   demanding is what keeps brief-following agents working — the briefs and the entrypoint
   are updated in **G7.5**, not here, so do not make `--branch` unconditionally mandatory
   on a verb the shipped briefs call without it.
3. **Operator-only verbs refuse agent sessions.** `cmd_reopen` and
   `cmd_blockers --set/--clear/--remove` rewire the DAG. They refuse outright when the
   caller is an agent session (`TASKPUMP_AGENT` set, or a `--branch` supplied), so only a
   human or the pump can restructure the graph.
4. **`cmd_claim` bounds the caller.** Refuse a claim from a branch that already holds a
   different `in_progress` task, unless an operator flag says otherwise. The ledger has
   every claim in `list --json`, so it is one scan.
5. **The transaction log names the actor.** `git_commit_state` appends the acting branch
   to every verb's message the way `claim` already does, and sets the git *author* from it
   so `git log --author` partitions the trail by agent. Record the actor in frontmatter
   too — prefer a single optional `last_mutated_by` over three parallel keys. It must be
   *optional* in `cmd_fsck`'s field table: `tests/test-tp-task-fsck.sh` is not in your
   footprint, so if that suite goes red you have widened the schema too far and the answer
   is to narrow the design, not to edit the suite.

### #130 — block accepts a done task and silently empties the frontier

`cmd_block` will block a task that is already `done`. It prints `blocked <id>`, exits 0,
and un-satisfies every dependent that had already cleared that blocker, because
`blockers_satisfied` requires every blocker to be exactly `done`. The entire dependent
subgraph drops out of the eligible frontier and nothing reports it — not `fsck`, not
`ready`, not `scrub`, not `blockers`. Observed on a fresh copy of
`tests/fixtures/generic-project`: `ready --count-eligible` went 1 → 0 after
`block T1 --reason "i say so"`, with `fsck` and `scrub` both silent at rc 0.

This is **not** covered by the claimant check above. A `done` task has `claimed_by: null`,
so a claimant check keyed on "when the task is claimed" leaves this path wide open. #83
authenticates the *actor*; this is a *state transition* that should not exist. Give
`cmd_block` the guard `cmd_release` already has one screen down: read `.status` and refuse
anything but `open` or `in_progress`, with a diagnostic that names `reopen` as the verb for
undoing a completion.

`docs/LEDGER-CONTRACT.md` §5.5 documents `block` as `* → blocked`, so the contract is as
much the gap as the code. §5.2/§5.4/§5.5/§5.7 change from unconditional transitions to
claim-conditioned ones, §3 gains the new key, §7's status table gains the refused source
states, and §9's audit-trail claim becomes true. `AGENTS.md`'s verb table gains the
refused source states on the `block` row, matching the way the `release` row already names
its condition.
