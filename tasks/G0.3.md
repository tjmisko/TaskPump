# G0.3 — Suites are hermetic against a consumer conf in the driven repo

## Spec

Discovered live on 2026-08-12, the first time the suites ran from a checkout
that carries a `taskpump.conf` (the dogfood conf added for the G ledger).
Evidence, in increasing severity:

1. **37 failures in `test-tp-pump`** when run from the primary after G0.1's
   (correct) sigil fix merged: every fixture uses `F55..F57`-style ranges and
   never sets a sigil, so the tools' config discovery — which walks up from
   `$PWD` and finds the *primary's* conf — handed them `TASKPUMP_PHASE_SIGIL=G`
   and the pump rejected the suite's own ranges. The identical suite is
   224/224 in a confless checkout.
2. **A full-suite baseline run hung inside `test-tp-pump` for over an hour**
   with zero output, under the PRE-fix pump code, from the primary. The
   suspected mechanism is the same leak through a different key:
   `TASKPUMP_TASKS_DIR=tasks` from the conf pointing fixture invocations that
   set no tasks-dir at the primary's real ledger (22 open tasks) — with
   whatever lock waits or tick loops that implies. Diagnosing the actual hang
   is part of this task; do not assume the suspicion is right.

The defect is structural, not G0.1's: **the suites claim hermeticity
("no checkout of any particular project") but inherit the enclosing repo's
conf through discovery.** Any consumer who vendors TaskPump inside a
configured repo and runs its suites hits this.

Fix direction (agent's judgment on the mechanism, but the seam should be
first-class, not per-test): give `lib/config.sh` an explicit off-switch —
e.g. `TASKPUMP_CONF=/dev/null` or `TASKPUMP_NO_CONF=1` honored before
discovery — and have `tests/run-all.sh` (and any suite runnable standalone)
export it, so fixture runs see only baked defaults plus whatever env the test
itself sets. Suites that *test* conf discovery must opt back in deliberately
with their own fixture conf.

## Scope

`lib/config.sh`, `tests/run-all.sh`, and the minimal per-suite changes for
standalone invocation. Do not weaken discovery for real callers — the
off-switch is explicit opt-out, not a default. Do not "fix" this by deleting
the dogfood conf.

## Acceptance

- `./tests/run-all.sh`: every suite green from the TaskPump primary WITH the
  dogfood conf present, and identically green in a confless checkout of the
  same commit.
- A regression test plants a poison conf (wrong sigil, wrong tasks dir) in a
  fixture's enclosing repo and asserts a suite-style invocation ignores it
  with the off-switch set, and honors it without.
- The baseline hang is explained in the completion notes with the specific
  key and code path, and a test covers that path.
- `docs/CONFIG.md` documents the off-switch.

## Completion notes (2026-08-13T04:13:47Z)

Fix: TASKPUMP_NO_CONF=1 in lib/config.sh suppresses the ambient discovery walk
(precedence: explicit TASKPUMP_CONFIG > the switch > the walk); run-all.sh and
every suite export it, with per-suite exports covering standalone runs.
test-tp-task's dual-invocation section — the one part that tests discovery —
opts back in per-invocation with TASKPUMP_NO_CONF=0.

The baseline hang, diagnosed: NOT the TASKS_DIR suspicion. The leaked key was
TASKPUMP_BUILD_GATE='./tests/run-all.sh' from the dogfood conf. test-tp-pump's
Test 13 integration ticks set no build-gate override, so run_build_gate_dry
eval'd the conf's command from the caller's cwd — the conf-carrying repo root —
and a gate-less integration tick re-entered run-all.sh, which re-entered
test-tp-pump, which ticked again: unbounded recursion with all output captured.
The sigil leak (TASKPUMP_PHASE_SIGIL=G vs F-range fixtures) caused the 37
visible failures. Both paths are pinned by tests/test-conf-hermeticity.sh with
a poison conf (wrong sigil, wrong tasks dir, marker build gate): ignored with
the switch, honored without, including the exact build-gate recursion cwd.

Verified green in all three contexts at the same content: the feat/g0-3
worktree with the dogfood conf (12 suites, 992 tests), a confless copy of the
identical tree, and the primary post-merge. docs/CONFIG.md documents the
switch.
