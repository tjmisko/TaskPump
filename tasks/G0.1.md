# G0.1 — pump_expand_phases honors the configured sigil and dies loudly

## Spec

Found by the first dry-run against this very ledger:
`tp pump --phases G1..G5 --dry-run` printed `bad phase range 'G1..G5'` *and
kept going*, planning against an empty phase list while reporting
`open tasks in range: 22`.

Two defects in `pump_expand_phases` (`tp-pump:281-296`):

1. **The sigil is hardcoded.** It strips `[Ff]` and re-emits `F%s`, while
   `tp-task`'s `expand_phases` (`tp-task:206`) already honors
   `TASKPUMP_PHASE_SIGIL` via `strip_phase_sigil`. Bring the pump's copy to
   parity — or better, source the one implementation, since the header comment
   already admits it "mirrors" the other. Single tokens and comma lists take
   the else-branch and pass through, which is why `--phases G1,G2` works today
   and is the interim workaround.
2. **The die is swallowed.** Both call sites (`tp-pump:1080,1162`) consume the
   function through a process substitution, so `die` kills the subshell and the
   pump proceeds on a truncated list — a malformed range produces exactly the
   "idling green on nothing to do" state PUMP-MECHANISMS exists to prevent.
   Validate `PHASES` once, up front, in the main shell, so a bad spec exits
   before the first tick.

## Scope

`tp-pump` only; `tp-task` is already correct. No contract change — this makes
the pump honor configuration that already exists.

## Acceptance

- With `TASKPUMP_PHASE_SIGIL=G`: `--phases G1..G5 --dry-run` plans all five
  phases; `--phases g1..g5` normalizes; comma lists and single tokens
  unchanged. The F-sigil golden runs are byte-identical.
- `--phases G1..X9 --dry-run` exits non-zero before printing a plan header,
  with the range error on stderr.
- `test-tp-pump.sh` gains a sigil-parameterized range case and a
  malformed-range-aborts case.
