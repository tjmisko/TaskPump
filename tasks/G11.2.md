# G11.2 — The injection corpus becomes a standing gate

## Spec

The security work in this range is spread across five drills built at five
different moments: G6.12's hostile ledger, G7.9's hostile conf and ledger-forgery
suites with `tests/fixtures/hostile-repo`, G8.1's brief-injection cases, G8.4's
provenance holds, G8.5's replay of the 2026-08-19 sweep. Each was written to prove
one phase's promise and each is a good suite. Together they are not a gate: nobody
can say, from the tree, which attack classes are covered and which were never
tested, and a guard removed in six months fails whichever of the five suites
happens to touch it — or none.

After this task there is one corpus with one manifest. Every payload class named
across the thirty-three security issues has at least one case, the corpus runs on
every push against the shipped tree, and `docs/THREAT-MODEL.md` says per tier what
it covers and — the harder half — what it does not.

### Derive the class list from the tracker, not from this file

Enumerate with `gh issue list --label security --state all --limit 200` and read
each issue's **Audit trail** line, which names the sweep finding it closes (B10,
NEW-SN-3, NEW-FC-1 and their siblings). The classes below are a seed, not the
list, and the completion note must record how the final list was derived so the
next person can redo it:

- conf sourced as shell under `set -a`, and the conf walk above the worktree (#77);
- pre-flight hook and agent settings resolved from inside the agent's own tree,
  and the pre-approving ruleset that follows from them (#78, #139, #82, #81, #126);
- repo-supplied build gate, `smoke_test.sh`, `cargo` executed on the host
  (#79, #117);
- forged ledger mutation and claimant impersonation — completing a sibling's task,
  ruling on your own review, raising your own budget, zeroing your own failure
  count (#83, #84, #85, #90, #130, #128);
- a task file from outside the trusted set reaching the frontier (G8.4);
- hostile content in a task file, a commit message, a branch name or a conf
  reaching a rendered brief or the operator's terminal (G8.1's fence);
- a ledger value reaching a host `eval` (`tp cleanup`'s `act()`);
- footprint overlap dispatched as disjoint (#91);
- a gate chain that cannot run reporting `GATE: feed-ok` (#122).

### What makes a corpus a gate rather than a museum

- **Refusal by name.** Every case asserts the *specific* refusal — the message
  that identifies the vector — not merely a non-zero exit. A payload that fails
  because a fixture path was wrong is a green case protecting nothing, and that is
  how corpora rot.
- **A manifest the suite checks.** Carry the class list in the suite as data, each
  entry naming its issue numbers and finding ids, and assert every entry has at
  least one case. An uncovered class must be a **failing assertion**, not an
  omission nobody notices. Print the covered/total count.
- **Against the shipped tree.** Drive the installed tools, hooks, gates and
  runners as an operator would, not a copy edited to be testable. A guard proved
  on a stunt double is not proved.
- **A mutation check per class.** Neutralising one guard must fail exactly the
  matching case and nothing else. Record the result in the completion note; it is
  the only evidence that the assertions are wired to the guards.

### Consolidate additively

`tests/test-hostile-ledger.sh`, `tests/test-hostile-conf.sh`,
`tests/test-ledger-forgery.sh` and `tests/test-brief-injection.sh` are **not** in
your `files:`. Consolidation here means the corpus becomes the single place that
answers "is class X covered", drawing on the shared fixture material under
`tests/fixtures/hostile-ledger` and `tests/fixtures/hostile-repo` — which are
yours, and which after G7.8's containment rule protect everything beneath them. It
does **not** mean deleting or rewriting those suites. Where that leaves genuine
duplication, record it as debt naming the suites and the owner it should go to.

Registration needs no workflow edit: `.github/workflows/ci.yml` runs
`./tests/run-all.sh` on push, and `run-all.sh` discovers `tests/test-*.sh` by
glob. Your declared edit to `run-all.sh` is for its hermeticity manifest and any
fixture globs the corpus needs declared there. That gate matters here more than
anywhere: this suite deliberately plants hostile files, and a corpus that leaves
one behind in the repo it was run from has demonstrated the attack rather than
refuted it. Work in `mktemp -d`, source `tests/suite-prologue.sh`, clean up on
`EXIT`, and leave the tree byte-identical.

### The documents

`docs/THREAT-MODEL.md` states, **per tier**, what the corpus covers and what it
does not. The second half is the one that earns trust: name the classes with no
case and say why (out of scope for this tier, needs a live container, needs a
second host), so a reader can tell an untested class from an accepted risk.
`SECURITY.md` points at the corpus by filename as the regression bar a fix is held
to — a reporter should learn from `SECURITY.md` alone what a patch has to pass.

## Scope

Six paths. Nothing enforces that but you.

**Two siblings are running beside you.** G11.1 owns
`.github/workflows/ci.yml`, `tests/test-generic-consumer.sh` and
`tests/fixtures/foreign-consumer`; G11.3 owns `README.md`, `docs/RUNBOOK.md`,
`docs/CONFIG.md` and `tests/test-docs-claims.sh`. If the corpus needs a dedicated
CI job rather than a place in `run-all.sh`, that is `ci.yml` and it is not yours —
record it as debt for G11.1 or the operator.

If a case proves a guard is **missing** — a class the range believed closed and is
not — stop. That is a finding, not a fixture bug. File it, name it in the
completion note, and leave the failing case in the corpus marked with its issue
number rather than deleting it or patching `lib/`, `libexec/`, `hooks/`, `gates/`
or `runners/`, none of which are yours.
