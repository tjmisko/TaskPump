# G1.6 — Flip ledger-shape defaults: probe, id grammar, workspace CLI

## Spec

The defaults that decide what a repository *is*:

1. **Ledger probe** — `TASKPUMP_LEDGER_PROBE` default `ops/task-loop/tasks` →
   `tasks` (`tp-task:52`; entrypoint's `TASKS_DIR` fallback
   `$LEDGER_REPO/task-loop/tasks` → `$LEDGER_REPO/tasks`, `entrypoint.sh:34`).
   The workspace-first resolution *mechanism* is untouched — only the probed
   path changes.
2. **Id grammar** — `TASKPUMP_ID_PATTERN` default `^F[0-9]+(\.[0-9]+)?$` →
   `^T[0-9]+(\.[0-9]+)?$`, sigil `F` → `T` (matches the README quickstart and
   the generic-project fixture). Separator stays `.`.
3. **Task CLI — BOTH keys** (G1.1's audit found the original spec here named
   one key with the other's line number): `TASKPUMP_WORKSPACE_TASK_CLI`
   default `scripts/arachne-task` → `tp` on `PATH` (`entrypoint.sh:134` — what
   the agent executes), AND `TASKPUMP_TASK_CLI` default `scripts/arachne-task`
   → `tp` (`tp-pump:122` — the spelling briefs quote at the agent). Flipping
   only one leaves briefs pointing at a CLI the container no longer runs.
   Until G4.3 mounts tp into the container, a bare
   container run won't find it: the entrypoint must fail loudly at startup —
   naming both fixes (`TASKPUMP_WORKSPACE_TASK_CLI`, or provide `tp` in the
   image) — rather than letting the agent discover a missing CLI mid-session.
   The templates read the CLI from config already; verify no template hardcodes
   the old path.

## Scope

Defaults, the entrypoint error path, and the fixture cleanup below. Making `tp`
*actually available* in-container is G4.3, deliberately post-tag.
