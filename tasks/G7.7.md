# G7.7 — The sandbox is defined from outside the tree it sandboxes

## Spec

The agent container is supposed to be a sandbox: a permission ruleset that sends dangerous
commands to the classifier, and an iptables egress allowlist with a verified DROP probe.
Both of those are files that live *inside the repository being worked on*. The tree under
audit configures the sandbox that is supposed to contain it.

This is the third of the plan's five named reasons for withholding an unattended drain, and
it is the one that a self-drain specifically breaks under: TaskPump's own `taskpump.conf:75`
pins `TASKPUMP_PRE_FLIGHT=./hooks/agent-preflight`, which resolves inside the agent's own
worktree, so an agent that edits the egress firewall gets that edit run as root with
`NET_ADMIN` on that branch's next relaunch — and under `--integration-trunk` it propagates
to every later worktree once the branch merges. A self-drain is exactly that configuration.

This is the widest task in G7: three issues, thirteen files. It is one control — policy
resolves from outside the tree — applied at each of its resolution sites. If the turn budget
runs short, **the plan's declared split point is: land #78 and #139 (the policy root and the
pre-flight) and complete; #82 (the base-ref and merge verbs) becomes a follow-on task.**
Split there and nowhere else — do not land half a policy root.

Line citations below are from the 2026-08-19 sweep and have already moved; at the time of
writing the pre-flight pin is still `taskpump.conf:75`. Search by name.

### #78 — agent permissions and the egress firewall are repo-carried

`hooks/agent-preflight` copies `$REPO_ROOT/claude-settings-auto.json` byte for byte over
`$AGENT_CLAUDE_DIR/settings.json` (the maintained path); `runners/claude-docker/entrypoint.sh`
has a legacy inline path that does the same when `TASKPUMP_PRE_FLIGHT` is unset. No
validation exists anywhere: the only thing that reads the file's shape is one log line,
`jq -r '.permissions.defaultMode // "default"'`, which shows the code *expects* that key to
be settable from this file. So a repository can ship a settings file that turns the
classifier off, or that carries a `hooks` block — a shell command that runs at session start
with `GITHUB_TOKEN` and the host's Claude OAuth access token in the environment.

The firewall is the same shape: the allowlist and the DROP probe are the body of
`hooks/agent-preflight`, which the entrypoint executes as root — after `cd "$WORKSPACE_PATH"`
and before the `setpriv` drop — with `--cap-add NET_ADMIN`. The file says so in its own
header: "The conf pins this file by its in-checkout path, so the copy that runs is the agent
worktree's own." A hostile fork replaces the body with `exit 0`; an agent rewrites it on its
branch without tripping the classifier, because Edit and Write are pre-approved.

A skeptic correction to carry: the two doors are mutually exclusive per configuration rather
than additive — `determine_pre_flight` reaches the legacy inline copy only when
`TASKPUMP_PRE_FLIGHT` is unset, and neutering `hooks/agent-preflight` to `exit 0` also skips
the settings copy inside that same file. Both doors are open; they are just not composable
through one route. Close both.

### #139 — the general form: no operator-owned policy root

#78 argues the direction for three specific files. #139 is the general control:
policy resolves from a root the repository cannot write, and a repo-carried variant is
**refused with a diagnostic naming it** — not merged, not preferred, not silently ignored.
Silent precedence is the defect class this project keeps finding. `docs/THREAT-MODEL.md` §5
names this as the second of the two controls that would make Tier 3 supportable.

After this task:

- `TASKPUMP_POLICY_ROOT`, defaulting under the operator's own configuration directory
  (`${XDG_CONFIG_HOME:-$HOME/.config}/taskpump/`), supplies agent settings (the
  `TASKPUMP_AGENT_SETTINGS` file #78 names), the MCP set, the pre-flight hook and the brief
  templates.
- `TASKPUMP_PRE_FLIGHT` must be an **absolute** path. Any value that resolves inside
  `$WORKSPACE_PATH` is refused with **exit 75** — `EX_TEMPFAIL`, which §10 already reserves
  for "environment not usable". Do not invent a code.
- The shipped hook is baked into the image (`runners/claude-docker/Dockerfile`) and
  `taskpump.conf:75` points at the baked absolute path instead of `./hooks/agent-preflight`.
- When a policy root is configured, a repo-carried variant of any of those files is refused
  with a diagnostic naming the file and the key that would allow it. Where a repo-carried
  settings file is still honoured for compatibility, run it through a schema filter that
  drops `permissions.defaultMode`, `hooks`, `mcpServers` and an empty `deny`, logging every
  key it drops by name.
- **The refusal is visible in `tp pump --dry-run`**, so an operator can see what a real run
  would refuse before starting it. This is why `libexec/tp-pump` is in your footprint.
- **With no policy root configured, behaviour is byte-identical to today's.** Existing
  consumers are untouched. Assert this; it is the acceptance criterion most easily lost.
- `runners/claude-docker/runner.sh` drops or narrows the read-write `$repo_root/.git` mount
  — narrow it to `$repo_root/.git/worktrees/<name>` plus a read-only object store — so a
  container shell cannot write the host primary's `.git/config` or `.git/hooks/*`.

### #82 — nothing stops an agent pushing to base or merging its own PR

The kickoff brief makes two promises to every agent: never touch the base branch, and never
merge. Neither is enforced.

The worktree shares the primary's ref database, so `git update-ref refs/heads/main HEAD`
from inside the worktree moves the primary's base branch and every worktree the pump cuts
afterwards starts from the agent's tree. No push, no network, no credential. `apl_fs_guard`
greps only `git status --porcelain`, so the pre-tick contamination hook sees nothing — a
moved ref is not working-tree dirt. The sweep's skeptic pass corrected the finding in the
direction of worse: the stated precondition (the primary must not have the base checked out)
is wrong. With `main` checked out, `git branch -f main HEAD` fails rc=128 but
`git update-ref refs/heads/main HEAD` still succeeds.

Separately, `claude-settings-auto.json` allows `Bash(git:*)` and `Bash(gh pr:*)` and its
entire deny list is docker, systemctl and sudo. So `git push origin HEAD:main` and
`gh pr merge --admin --squash` are the two commands the brief forbids and the two the
harness has been configured never to review. `hooks/agent-preflight` states the intent
outright — the allow rules keep routine commands off the classifier so the
abort-after-repeated-blocks ceiling stays distant — and `taskpump.conf:75` makes this the
shipped default configuration.

After this task, two layers, because a permission list is advice to one agent implementation
and not a boundary:

1. `claude-settings-auto.json` denies push-to-base and every merge verb — narrow the git
   allow to the read and commit verbs the brief actually asks for and let push reach the
   classifier, and deny `Bash(gh pr merge:*)`, `Bash(gh pr review:*)`, `Bash(gh api:*)`.
   No allow entry may be broad enough to shadow a deny. `hooks/agent-preflight` then *fails
   the pre-flight* when the installed ruleset lacks those denies, exactly as its firewall
   DROP probe is already fatal.
2. Make the ref unwritable and notice when it moves. With the `.git` mount narrowed per #78,
   a base-ref update from the worktree should fail; if the wide mount must stay, install a
   `reference-transaction` hook in the primary rejecting updates to `refs/heads/$BASE_REF`.
   Independently, `libexec/tp-pump` records `BASE_REF`'s sha at tick zero and refuses to
   launch — loudly, as a deadlock, **exit 3**, the code §10 already reserves for "nothing may
   proceed" — when the ref has moved without the pump moving it. `apl_fs_guard` in
   `lib/pump-lib.sh` grows a ref-drift check beside its working-tree check so the pre-tick
   hook actually covers this.
