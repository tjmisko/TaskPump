# G7.3 — The pump runs nothing the repository supplied, and refuses a gate it cannot run

## Spec

`tp pump` is a supervisor: it cuts worktrees and launches agents in containers. Three of
its defaults reach outside that boundary and run code the *repository* chose, on the host,
unsandboxed, with the operator having configured nothing. In a self-drain, "repo-supplied"
means "agent-supplied": an agent that adds a `smoke_test.sh`, or edits the build-gate value
in the workspace conf, gets host execution on the next tick. That is why this task is one
of the five reasons the plan's `safe_to_self_drain_after` gives for withholding unattended
operation until G7 is drained.

The same file carries the other half of the same problem from the other direction: a gate
the pump *cannot* run is skipped with one line on stderr and then announced as
`GATE: feed-ok` on stdout. An operator who typos a gate path gets a plan indistinguishable
from a chain that ran and approved, and a pump that launches with no gate at all.

This task blocks on **G6.13**, the v0.2.2 tag, and that blocker is load-bearing rather
than ceremonial. A task-grain range run plans every phase in range in one tick, so without
the barrier the scheduler would dispatch these MINOR default changes beside the patch line
and they would ship inside a PATCH tag.

Three issues, one function family. Line citations below are from the 2026-08-19 sweep and
have already moved once; at the time of writing `run_build_gate` is at
`libexec/tp-pump:1841`, `run_build_gate_dry` at `:1857`, `IMAGE_BUILD_CMD` at `:200`, the
two submodule call sites at `:1717` and `:1832`, `gate_chain_line` at `:1203`, `feed_gate`
at `:1248` and `run_pre_tick_hooks` at `:2517`. Search by name; the numbers are a starting
point.

### #79 and #117 — the build gate, the image build, the submodule fetch

**These two issues are literally the same edit to `run_build_gate` and must not be
separated.** #79 is the security reading (the repo supplies the code the host runs); #117
is the portability reading (any non-Rust consumer has every phase quarantined). One
deletion closes both.

`run_build_gate` today is: run `BUILD_GATE_CMD` if set; otherwise run
`cargo check --workspace`, and then `./smoke_test.sh` if the worktree ships one. `cargo
check` compiles and executes `build.rs` scripts and proc-macro crates, so leg (b) is
unconditional on that path even though `./smoke_test.sh` only runs when cargo first
succeeds. And on a consumer with no `Cargo.toml`, cargo exits 101, so the merge that just
succeeded is `git reset --hard`ed away, the unit is quarantined as `build red`, the phase's
lead task is flipped to `needs-review`, and the operator is paged for a phase whose work is
completely fine. Observed in a fixture: `quarantine T1: build red` with
`TASKPUMP_BUILD_GATE` unset, and `integrated T1 @ d302d53e` with
`TASKPUMP_BUILD_GATE=true`.

The rehearsal cannot catch it, because `run_build_gate_dry` runs only an
explicitly-configured command and returns green otherwise. So
`tp pump --integration-trunk --dry-run` reports every unit integrable and the first real
tick quarantines all of them.

After this task: delete the `cargo check --workspace` and `./smoke_test.sh` arms. An empty
`BUILD_GATE_CMD` means **no build gate**: return green and log a named line once per run
("integration trunk absorbing merges ungated; set TASKPUMP_BUILD_GATE to gate them"). That
is exactly the stance the pump already takes for `RECLAIM_CMD` — its own comment says "only
a consumer knows how its build output is reclaimed, so there is no built-in fallback (G1.7
retired the cargo one)". The build gate kept the fallback that reclaim dropped. The change
also makes `run_build_gate` and `run_build_gate_dry` agree, closing the rehearsal/real-run
asymmetry for free. The key-resolution comment that still says "empty ⇒ default cargo check
+ smoke" becomes the documentation of the new rule.

`IMAGE_BUILD_CMD`: remove the implicit `docker build -t "$IMAGE" "$REPO_ROOT"`. Every `RUN`
line in a repository's `Dockerfile` currently executes as root with network before any
pre-flight firewall exists. When `TASKPUMP_IMAGE` is set and `TASKPUMP_IMAGE_BUILD` is
unset, `die` naming both keys, with the same loudness the pump already uses for a missing
image.

Submodules: both call sites run `git -C "$wt" submodule update --init --recursive` with the
outcome swallowed by `2>&1 | tail -1 || true`, on every launch, fetching whatever URLs the
repo's `.gitmodules` names. Put it behind a new `TASKPUMP_SUBMODULE_INIT` (default off).
When it does run, capture the exit status and `warn` with git's own `fatal:` line instead
of swallowing it, and pin the transport policy at the call site —
`git -c protocol.ext.allow=never -c protocol.file.allow=never …` — so the defence does not
depend on the host git's defaults.

`tp init` is the other half of #117 and it is not optional: the scaffold writes
`TASKPUMP_BUILD_GATE` as a *commented-out* line, so the configuration TaskPump itself
produces for a new consumer is exactly the broken one. Write the key uncommented with a
value the consumer must fill in, or have `tp init` refuse to scaffold `--integration-trunk`
usage without one. The scaffold must stop emitting a build gate a non-Rust repo cannot
pass.

### #122 — an unrunnable gate or hook fails open

`feed_gate` splits each newline-separated entry on whitespace and skips it with
`warn "gate not executable, skipping: $1"` when the first word is not executable. `warn`
writes to stderr; `log` and `print_plan` write stdout. `gate_chain_line` uses the same
split but never applies the `-x` test, so the display line names a plausible gate that will
not run. `run_pre_tick_hooks` has the identical shape, so a typo silently disables
`fs-guard`, the contamination guard.

Four observed shapes, all ending in `GATE: feed-ok`:

1. Bare name. `TASKPUMP_GATES='claude-usage'` → stdout `gates: claude-usage`,
   `GATE: feed-ok`; the skip is on stderr only.
2. Comma-separated. Two absolute paths joined by a comma → stdout `gates: disk-low`, the
   basename of the whole blob, naming one gate that is not running. Both gates off.
3. Conf-relative path. `TASKPUMP_GATES='gates/mygate'` with an executable gate that exits
   10: from the repo root, `GATE: PAUSED`. From a subdirectory of the same repo with the
   same conf, `GATE: feed-ok`. `TASKPUMP_GATES` is not in `lib/config.sh`'s
   `TP_ANCHORED_PATH_KEYS`, so the gate works or does not depending on where the operator
   was standing.
4. Hooks. `TASKPUMP_PRE_TICK_HOOKS='gitignore-repair' tp pump --once` proceeded normally
   with the hook chain silently empty.

After this task, both halves:

- **Disclosure.** Push the skip into `GATE_NOTES` as well as calling `warn`, so
  `print_plan`'s existing note loop renders `mygate: SKIPPED — not executable` on
  **stdout**, and mark unrunnable entries in `gate_chain_line` (e.g. `mygate(!)`) so the
  display line stops asserting a chain that will not run.
- **Refusal.** Validate the whole chain **once at startup**, before the tick loop, and
  `die` naming the offending entry. Under `--dry-run`, exit non-zero — `docs/GATES.md`'s own
  verification recipe is currently a grep for `skipping`, which is an admission that the
  exit code does not tell you; it becomes an exit code. Apply the same validation to
  `run_pre_tick_hooks` in the same pass. A comma-separated value is rejected with a message
  that says the separator is a newline.
- **Relative first words.** Decide one of two things and say which in `docs/GATES.md`:
  anchor the first word of each line against the conf's directory, or refuse a relative
  first word outright at the same startup validation. Leaving it `$PWD`-relative is what
  makes case 3 depend on the operator's working directory, and that is not an acceptable
  outcome. Note that `TASKPUMP_GATES` is a newline list, so the existing scalar anchoring
  mechanism in `lib/config.sh` does not apply as-is — and `lib/config.sh` belongs to
  **G7.1** this wave, so the per-line anchoring must live in `libexec/tp-pump`.

`tests/test-golden-plan.sh` will need regenerating: the plan grammar gains the note line
and the `(!)` marker.
