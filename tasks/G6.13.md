# G6.13 — The contract's exit-code notes are true, and v0.2.2 is tagged

## Spec

The phase's tail task. Three jobs: correct two conformance notes in the frozen
contract (#69, #70), land the documentation debt every other G6 task recorded,
and cut the tag. It blocks on all twelve siblings, so when you start you are the
only writer in the phase.

**Read every `tasks/G6.*.md` completion note before you touch anything.** They
are this task's real input. The plan's rule is that `CHANGELOG.md` and `VERSION`
belong only to a phase's tail task, and that every other shared document has
exactly one owner per phase — so twelve tasks have been recording sentences they
were not allowed to write. This task owns `docs/CONFIG.md`, `docs/CLI-TOOLS.md`,
`docs/RUNNERS.md` and `taskpump.conf.example` for G6, which is where most of
that debt lands.

Why VERSION and CHANGELOG are held back to one task: the project's own
precedent, `tasks/G2.3.md`, which cut v0.1.0 owning `VERSION` and `CHANGELOG.md`
and nothing else. Siblings dispatched concurrently each appending to a changelog
collide on every merge, and a half-written changelog produces a release note
that is wrong about the release it names — which is the one document an operator
reads to decide whether to upgrade.

### #69 — §10.1's state-file remedy is stale

`docs/LEDGER-CONTRACT.md` §10.1 (around `:760-762`) is what a consumer is told
to key on: it admits `tp pump`'s exit 0 is ambiguous and then says to read the
state file instead, "because the pump stamps a terminal status into it on every
exit path, including the signal handlers". That sentence is false. Six of the
eight invocations reaching `exit 0` never call `write_state`: `--render-brief`,
`--render-resume-note`, `--dry-run`, `--list`, `--help` and `--detach`. Only
`--once`, the loop's drain exit, `stall_exit` and the EXIT/INT/TERM/HUP traps
write it — and the traps are installed *after* the mode dispatch on purpose, so
a pump that never ticked never clobbers a previous run's file. The file carries
no field identifying which invocation wrote it, so a careful reader cannot
recover the truth either: a repository whose last real run deadlocked answers
`stalled` to a supervisor that just ran a plan print and got 0.

After: replace the universal-stamping sentence with an explicit two-column
split — the paths that stamp, named, and the six that do not, named. State
plainly that after a non-loop invocation the file describes an **earlier** run
and that no field identifies the writer. Give the rule that actually works
against this release, as a compound rule: the argv must be loop mode (none of
`--once`/`--dry-run`/`--list`/`--render-*`/`--detach`/`--help`), exit 0, and
`.status == "drained"` — with `status` alone explicitly insufficient and a
`--detach` 0 explicitly meaning "handed off", never an outcome. Extend §10.1's
exit-2 inventory (around `:724-738`) with the four shipped commands it omits and
their actual statuses: `tp monitor` 1, `tp dag-render` 1, `tp usage` 1,
`tp stream-fmt` 0 — the last parses no arguments at all, which also makes
`bin/tp`'s blanket promise that every command answers `--help` untrue for it.
Cross-link `docs/CLI-PUMP.md` §2.1, which already gets this right, so the two
stop being independently maintained accounts of one fact; and add to
`docs/CLI-PUMP.md` (around `:169-172`) that the file the reader is looking at
may belong to a previous run.

The frozen table (around `docs/LEDGER-CONTRACT.md:692-707`) must be
**byte-identical** afterwards. §10 says the codes are frozen and changing one is
MAJOR; §10.1 is the per-release conformance note and is the only thing that
moves here. No code changes in this issue.

### #70 — §10 omits exit 2's second meaning and 75's missing consumer

Two rows are true but incomplete in the direction that silently blinds a
supervisor.

Row `2` says "Bad CLI arguments. Consumer: Humans." In the runner protocol exit
2 from `<runner> list` is a **machine-read capability answer** meaning "I do not
implement this verb". `apl_runner_list_supported` (`lib/pump-lib.sh` around
`:371-383`) probes it once and caches the answer in `APL_RUNNER_LIST_CAP` for
the life of the process, so a v2 runner that exits 2 because its runtime was
briefly unreachable during the startup probe is classified "no `list` verb"
forever, after which every agent reads as dead and the supervisor relaunches
over all of them. `docs/RUNNERS.md:203-223` documents the consequence in full
and neither §10 nor §10.1 mentions it.

Row `75` names "The launcher, which may retry without burning a tripwire" as its
consumer. That consumer does not exist: nothing in this repository reads a
launched agent's exit status, and `docker run --rm -d`
(`runners/claude-docker/runner.sh` around `:281`) plus `setsid`+`disown`
(`runners/local/runner.sh` around `:413-416`) destroy it by construction. The
promised outcome nevertheless holds, but **structurally**: an entrypoint that
exits 75 before `heartbeat --start` leaves nothing claimed, so the task stays
eligible and the next tick relaunches it. And 75 has an in-tree homonym —
`APL_LIVENESS_DEGRADED_RC` (`lib/pump-lib.sh` around `:385-394`), a function
status meaning "this liveness answer is a fallback scrape, not authoritative",
which is process-internal and not a wire code at all.

After: a **new §10.2 conformance note** inserted after the §10.1 material —
addition only, the frozen table is not edited. §10.2(a): exit 2's capability
meaning, the once-per-process cache, the permanent misclassification, and the
one-line rule repeated verbatim so a reader who never opens RUNNERS.md still
gets it ("reserve 2 for a verb you genuinely do not implement; use 1 or 75 or
anything else for a transient failure"), cross-linked both ways with
`docs/RUNNERS.md`. §10.2(b): 75's guarantee is structural and a consumer must
not key a retry on it; 75 also names an internal function status a runner must
read nothing into. `docs/RUNNERS.md`'s pre-flight 75 guidance says what does and
does not observe the 75. `docs/CLI-TOOLS.md`'s dispatcher exit-2 description
points at §10.2 rather than implying 2 is uniformly a usage code.

Deliberately out of scope: moving the capability probe off 2 onto a dedicated
code. That is the collision the frozen table papers over, it is MAJOR, and it
belongs in its own issue rather than smuggled into a docs patch.
