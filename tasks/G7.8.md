# G7.8 — The footprint is a grammar the scheduler can trust

## Spec

The pump schedules two tasks concurrently only when their declared `files:` sets are
disjoint, and the brief tells the agent so in as many words — "the pump scheduled you
concurrently with your siblings *because* those sets are disjoint" — while admitting that
nothing but the agent enforces the list. The second half is true. The first half is also
false.

This is the fifth of the plan's five named reasons for withholding an unattended drain:
until this lands, the concurrency the whole drain depends on is a string comparison, and two
siblings whose footprints overlap can be dispatched into two worktrees in the same tick from
a plan that reads clean. The ledger this task file lives in was itself checked mechanically
against both the old rule and the new one to survive that gap — which is the measure of how
little the current check gives you.

One issue, #91. Line citations below are from the 2026-08-19 sweep and have already moved;
at the time of writing `unit_files_conflict` is at `libexec/tp-pump:815`, its caller at
`:846`, and `cmd_create` at `libexec/tp-task:2912`. Search by name.

### The comparison

`unit_files_conflict` is `comm -12` over two `sort -u`'d literal lists. No normalisation
exists anywhere on the path: `task_files` is a raw split of the snapshot blob,
`load_task_snapshot` is a `jq` join of the stored strings, and the write side in
`libexec/tp-task` transforms only with `tr -d '[:space:]'`. So `lib/` and `lib/a.sh` share
no line and read as disjoint, as do `lib/a.sh` and `./lib/a.sh`, and any glob against any
concrete path. Reproduced through the real supervisor: three tasks whose footprints all
cover `lib/a.sh` planned as three `LAUNCH` lines, "3 launchable, 0 waiting", and the brief
rendered for the second still told its agent the sets were disjoint.

No downstream catch exists. `tp task fsck` exits 0 on that ledger, and `cmd_complete` never
reads `.files`. Anyone who can author or amend a task file — which includes a stranger's
pull request touching `tasks/`, since the ledger is in-tree in the default shape — chooses
the spelling, and can pick one that defeats the check while looking honest.

After this task, four changes:

1. **Define the grammar.** `docs/LEDGER-CONTRACT.md` §3 states what a `files:` entry may be:
   a repo-relative path, no leading `./`, no `..`, no absolute path, no glob metacharacters,
   a trailing `/` meaning "this directory and everything under it". §3 today defines the
   field only as "Repo-relative paths" — no normalisation, no prefix semantics, no glob
   semantics anywhere — which is why tightening the comparison is a contract change rather
   than a bug fix in isolation.
2. **Normalise and compare by containment.** In `unit_files_conflict`: strip `./`, collapse
   `//`, drop a trailing `/` before comparing, then treat two entries as overlapping when
   either is a **path-component** prefix of the other. `lib/` overlaps `lib/a.sh`; `lib/a`
   does **not** overlap `lib/ab`. The component boundary is the whole point — a plain string
   prefix gets `lib/ab` wrong.
3. **Refuse what cannot be compared.** `cmd_create` and `cmd_fsck` in `libexec/tp-task`
   reject entries containing glob metacharacters, `..` or an absolute path, so the scheduler
   is never handed something it cannot reason about. `fsck` reports an existing one as a
   violation and exits **3** — the code `docs/LEDGER-CONTRACT.md` §10 already reserves for
   ledger violations. Do not invent a code.
4. **Name the overlap in the wait.** When containment serialises a pair, the `WAITING` line
   says which path overlapped, so an operator reading the plan can see why. A wait reason
   that does not name the file is the shape this project keeps having to fix.

`templates/task-brief.md`'s concurrency sentence must state what is actually guaranteed once
(2) lands, rather than a disjointness the comparison did not provide.

#91 also proposes a fifth change — `cmd_complete` diffing the branch against its base and
reporting paths touched outside the declared footprint. Land it as a **report**, not a
refusal: that is the check the brief's "nothing enforces the list but you" is asking for, and
a refusal at completion time would strand finished work. Put any refusing behaviour behind a
config key, default off.

### The note later phases depend on

Record in `docs/LEDGER-CONTRACT.md` §3, explicitly and as a dated statement of the new rule,
that **from this point a ledger may declare a directory entry and be protected by it.** Until
now, every task file in this project has had to spell out concrete paths and avoid mixing a
directory with a file inside it, because the comparison was exact-string. Task files written
for G8 onward rely on your note to widen their footprints — G8's drill declares
`tests/fixtures/hostile-ledger` and means it. If the note is missing, the next planner has no
way to know the guarantee exists.

### Inherited from G7.6

G7.6 landed `fsck --drift` and handed you the pre-tick wiring, because `libexec/tp-pump` is
yours and not its. Read G7.6's completion note for the exact invocation, exit code and
message shape, and wire it into the pump's pre-tick preflight beside `scrub`, so a drifted
ledger stops the drain rather than being read as truth. A clean ledger must not stop it.

## Scope

The declared `files:` list is `libexec/tp-pump`, `libexec/tp-task`,
`docs/LEDGER-CONTRACT.md`, `templates/task-brief.md`, `tests/test-tp-pump.sh` and
`tests/test-pump-lib.sh`. Nothing enforces that list but you — and this is the task that
makes that enforcement mean something, so widening it quietly would be the joke this project
cannot afford. This round is one-wide: nothing is scheduled beside you.

`tests/test-tp-task.sh` is **not** yours. Drive `tp task create` and `tp task fsck` as
external commands from `tests/test-tp-pump.sh` for the grammar-rejection assertions rather
than editing the tp-task suite. If any of `tests/test-tp-task.sh`,
`tests/test-tp-task-fsck.sh`, `tests/test-tp-task-review.sh`,
`tests/test-tp-task-generic.sh` or `tests/test-golden-plan.sh` goes red, that is a signal
your grammar refuses something a legitimate existing ledger says — narrow the rule, do not
edit the suite. Note that this repository's **own** `tasks/` directory is a legitimate
existing ledger and must pass the new `fsck`.

`docs/PUMP-MECHANISMS.md` is not yours: record the pre-tick drift documentation as debt.
`CHANGELOG.md` belongs to **G7.9** — record the entry, which is substantial: a ledger that is
legal today (`./lib/a.sh`, `src/**`) becomes a violation, and pairs that schedule
concurrently today will serialise.
