# G6.10 — No probe failure is replaced by a number

## Spec

One issue, #102, closing two sweep findings that share a root cause: a GNU-only
invocation with no fallback and no guard, whose failure is swallowed by
`2>/dev/null` and replaced with a plausible-looking number. Read the issue with
`gh issue view 102`. The file:line citations below are copied from its evidence
and all of them move once you start editing — find each site by its command
(`rg -n 'df --output|stat -c|date -d|du -sb|sed -i'`), and treat the numbers as a
starting point.

The rule this task establishes, and which the acceptance pins: **no probe
failure is ever replaced by a number.** A tool that could not read says so.

### The destructive half — the disk watchdog

`libexec/tp-disk-watchdog`'s probe (around `:110-114`) defaults to
`df --output=avail -BG '$MOUNT'`, which is GNU-only, and pipes it through `awk`
with the failure discarded:

```bash
free_gb() {
    if [[ -n "${FREE_GB_OVERRIDE:-}" ]]; then echo "$FREE_GB_OVERRIDE"; return 0; fi
    eval "${TASKPUMP_DISK_PROBE:-df --output=avail -BG '$MOUNT'}" 2>/dev/null \
        | awk 'NR==2 {gsub("G",""); print $1}'
}
```

The watch path (around `:166-172`) then defeats its own guard: `g="$(free_gb ||
echo 0)"` means the `[[ -z "$g" ]] → log WARNING, skip the check` branch written
two lines below can never fire, because `g` is never empty. So on any host whose
`df` is not GNU — macOS, the BSDs, any busybox image — the watchdog concludes
**0 GB free** on its first check, writes a pool cap of 0 so every future launch
is paused permanently, and runs its panic reclaim: `docker builder prune -af`
and `docker system prune -f`, destroying the host's entire container build cache
on a machine that may have terabytes free. The operator sees
`/ free=0G — HEALTHY → PANIC` and a truthful-looking log line. One file away, the
`--gate` path (around `:202-206`) handles the identical unreadable value
correctly — `|| echo ""`, then "free=unknown — failing open". One broken probe,
two contradictory answers from one tool.

After: `free_gb` returns the empty string when the probe fails — test the
pipeline's status explicitly rather than relying on `pipefail` reaching the
caller, since `:37` is `set -uo pipefail` — and `react()` takes
`g="$(free_gb || echo "")"` so it reaches the WARNING branch already written.
The watch path and the gate path then agree. Default the probe to something
portable: `df -Pk "$MOUNT"` with an awk that converts 1K-blocks to GB.
`libexec/tp-monitor` around `:808` already uses `df -Pk`, so the spelling exists
in the tree. `TASKPUMP_DISK_PROBE` stays as the override.

### The four quiet sites

Each has the same `2>/dev/null || <plausible value>` shape:

- `gates/claude-usage:87` — `stat -c %Y … || echo 0`. Falling back to `0` makes
  the cache age `now - 0` ≈ 1.8e9 seconds, always greater than
  `TASKPUMP_USAGE_TTL`, so the meter re-probes on every paint. Same shape at
  `libexec/tp-monitor:505`, `:509`, `:524`, `:963`.
- `gates/claude-usage:178` — `date -d "$iso" +%s 2>/dev/null || printf ''`,
  feeding `cmd_scan_logs` (around `:294-299`) and `reset_epoch` (around `:198`).
  An empty conversion means `--scan-logs` never arms the usage-reset backstop,
  so the pump keeps launching agents into a hit limit. Also `:243`, `:303`, and
  `libexec/tp-monitor:414`.
- `libexec/tp-monitor:787` — `du -sb --exclude=…`. Both `-b` and `--exclude` are
  GNU-only; the result is an empty size and a blank disk breakdown.
- `lib/pump-lib.sh:164` — `sed -i "/^$esc\$/d" …`. BSD `sed -i` requires a
  backup-suffix argument, so this is a syntax error there and the gitignore
  repair silently stops repairing.

After: three shims in `lib/pump-lib.sh` beside `apl_docker` — `apl_mtime <path>`
(`stat -c %Y` then `stat -f %m`), `apl_iso_epoch <iso>` (`date -d` then
`date -j -f`), and `apl_sed_i` (GNU form vs `-i ''`) — and every site above
routed through them. Replace `du -sb --exclude` with POSIX `du -sk` minus the
worktrees, or a `find`-based sum. `libexec/tp-cleanup:224` is the one correct
instance in the tree today (`stat -c '%Y' … || stat -f '%m' … || echo 0`) —
route it through `apl_mtime` too, so there is one implementation rather than
two, and drop its `|| echo 0` tail so it obeys the same rule as everything else.
Where a shim genuinely cannot answer it returns empty and the caller says so.

### The undeclared requirement

Nothing in the tree declares the dependency. `README.md:38-40` names `bash` 4+,
`git`, `yq`, `jq` and `awk` and stops. `docs/CONFIG.md:795` documents the
`df --output=avail -BG` default verbatim without noting it is GNU-only, and
`docs/CLI-TOOLS.md:550` describes the watchdog's three-state machine with no
unreadable state. CI cannot catch any of it: `.github/workflows/ci.yml` runs
`ubuntu-latest` on both legs and installs `coreutils`, so the suite only runs
where the assumption holds.

After: `docs/CLI-TOOLS.md`'s disk-watchdog section gains the unreadable state
and says what the tool does in it (warn, no transition, no cap write, no prune).
`.github/workflows/ci.yml` gains a leg that puts BSD-shaped stubs for
`df`/`stat`/`date`/`du`/`sed` ahead of the GNU tools on `PATH` and runs the
suite — a macOS runner is acceptable if it is cheaper to maintain, but the stub
leg is the one that pins the behaviour deterministically. `README.md` and
`docs/RUNNERS.md` also need a requirements line; neither is yours — see Scope.
