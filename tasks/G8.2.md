# G8.2 — The agent's transcript never reaches a pull request

## Spec

The runner writes the agent's complete session transcript — every prompt, every
assistant turn, every tool result — to `.taskpump-agent.log` at the root of the
agent's worktree, next to three other supervisor-written files. None of the four is
gitignored, here or in a consumer repo scaffolded by `tp init`. Two paths then commit
that untracked content: the stuck-agent rescue snapshot in `libexec/tp-cleanup` runs
`git add -A` over the whole worktree and commits it, and the agent's own brief tells
it to commit early and often. The branch is merged into the integration trunk, the
trunk is pushed, a PR opens. Anything the session read — a repo `.env`, the
`~/.claude.json` the agent inherits, the output of `env` — goes to the remote inside
it.

This is **#88**. Its citations have drifted; re-derive by symbol. The rescue snapshot
it cites at `libexec/tp-cleanup:251-252` is at `:350-352` today, inside the stuck
sweep, and the fs-guard allowlist it cites at `lib/pump-lib.sh:584` is
`APL_FS_GUARD_ALLOWLIST` at `:737`.

After this task, every run file the tools write is either ignored in `.gitignore` or
allowlisted in `APL_FS_GUARD_ALLOWLIST` — never in neither, and never in both.

### The invariant `.gitignore` states and does not keep

`.gitignore`'s own header (lines 1–5) states the rule this violates:

> a run file that is tracked here but allowlisted there is a dirty tree nobody
> notices, and one that is neither is a warning every tick

Measured in the primary checkout, `git check-ignore -v --` returns NOT IGNORED for all
five of `.taskpump-agent.log`, `.taskpump-resume.md`, `.taskpump-goal.md`,
`.taskpump-phase-brief.md` and `.taskpump-rotest`. They escape the every-tick
contamination warning only because the fs-guard allowlist blanket-allows
`^\.worktrees/`. Add the five names and their `.arachne-` twins to `.gitignore`,
keeping the file's stated agreement with the allowlist. Do **not** add a bare
`.worktrees/` line — `hooks/gitignore-repair` deletes it every tick and the header
explains why (the 2026-04-14 incident).

The writers, for the audit: `runners/claude-docker/entrypoint.sh` sets
`LOG_FILE="$WORKSPACE_PATH/$AGENT_LOG_NAME"` (default `.taskpump-agent.log`) and tees
the session into it; `libexec/tp-pump` writes `.taskpump-resume.md`,
`.taskpump-goal.md` and `.taskpump-phase-brief.md` into the worktree. Enumerate the
writers yourself rather than trusting this list — the acceptance below is "no file is
in neither", which is a claim about the set, not about five names.

### A scaffolded consumer starts with nothing

`libexec/tp-init` writes `taskpump.conf` and creates the tasks directory (cited
`:160-193`; the file is 193 lines, so that is most of it) and writes no `.gitignore`
at all. A freshly scaffolded consumer's first tick reports every run file as primary
contamination and pushes a desktop notification for it. `tp init` must write — or
**append to** — a `.gitignore` at the scaffolded root carrying the same names. Append,
not clobber; idempotent across repeated runs, which means checking for the lines
before adding them rather than counting on a marker comment nobody will preserve. This
is the new behaviour in this change and the reason it is not a patch.

### The rescue snapshot must not be able to publish

`libexec/tp-cleanup`'s stuck sweep runs `act git -C "$wt" add -A` and commits. Narrow
the pathspec to `git add -A -- ':!.taskpump-*' ':!.arachne-*'` so the transcript cannot
be published even from a repo whose ignore file is stale — belt as well as braces,
because the ignore file is the consumer's to edit and this path is a documented
recovery route.

Sequencing note carried from the issue: that call was an `eval`ed string and is being
converted to an argv vector by **#80**, the shell-injection issue. In this tree it is
already the vector form (`act git -C "$wt" add -A`), so add the pathspec as further
arguments to the vector. If you find the string form, **#80**'s owner has not landed
and you should say so rather than reverting their shape.

### The hook's comment must describe the allowlist it has

`hooks/fs-guard`'s header says agents work inside worktrees "and the primary checkout
is mounted read-only in their containers, so this should always be silent" — which is
not true under `runners/local` or under the collapsed single-repo docker mount, and
says nothing about which run files the allowlist covers versus which the ignore file
covers. Rewrite the header to describe the arrangement it actually enforces, and bring
`docs/GATES.md`'s `fs-guard` bullet (cited around `:550-566`) into agreement: it
currently states the allowlist "has **no entry** for the supervisor's own state files"
and that they "stay quiet only because `git status` does not report ignored paths".
That sentence stays true and becomes the *documented design* rather than an accident —
say which set is covered by which mechanism and why the ignore file is the right repair
for a new run file.

## Scope

The seven paths in `files:` above and nothing else. Nothing enforces the list but you.

Do not touch:

- **`lib/pump-lib.sh`.** `APL_FS_GUARD_ALLOWLIST` lives there and you may need to read
  it, but the fix here is on the ignore side by design — the allowlist is a blunt
  instrument (`TASKPUMP_FS_GUARD_ALLOWLIST` replaces the whole pattern) and
  `lib/pump-lib.sh` is **G8.1**'s, running concurrently with you in the same tick.
  Adding a line to it collides with the sibling the scheduler dispatched beside you.
- **`runners/claude-docker/entrypoint.sh`** — also G8.1's this tick. Read it to
  enumerate the writers; change nothing in it.
- **The credential contents of the transcript.** Stripping what the agent may read is
  **G7.4**, already landed. This task only stops what is written from being published.

`docs/CONFIG.md`, `taskpump.conf.example` and `CHANGELOG.md` belong to **G8.5**, the
phase tail. Record your doc debt in the completion notes for it, including the
CHANGELOG entry: MINOR (v0.3.0), because `tp init` gaining a `.gitignore` it did not
write before is new scaffolding behaviour in a consumer's repository and the rescue
snapshot's pathspec changes what a documented recovery path commits. No exit code and
no row of `docs/LEDGER-CONTRACT.md` §10 moves.
