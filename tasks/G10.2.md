# G10.2 — A launched agent can work from AGENTS.md and its brief alone

## Spec

An agent the pump launches gets one pass at `AGENTS.md` and its rendered brief,
and cannot ask a follow-up question. Every sentence in those files is therefore a
promise executed by a stranger. Today nothing checks them: a verb the tools no
longer accept, a flag that was renamed, a status the contract never defined, or a
`{{PLACEHOLDER}}` the renderer does not fill all ship silently and are discovered
by an agent burning a turn on a usage error at 3am.

This task makes those documents a contract that a suite enforces, and repairs
what the suite finds.

**Two failure directions, and the second is the one this range created.** The
familiar one is the document naming something that does not exist. The new one —
because G7 landed the trust boundaries and G8 landed provenance — is the document
denying a guard that now *does* exist. `AGENTS.md`'s table under "Boundaries, and
what actually enforces them" (around `:210-230`; line numbers move, anchor on the
`| Boundary | Enforced by | Issue |` header) currently tells every launched agent
that **Nothing** enforces "only your task", "never merge your own PR", "stay
inside your declared `files:`", "the ledger has one writer" and "your turn budget
bounds you", and cites #82, #83, #84, #85, #90, #91 as open. By the time this task
runs, G7.2's claimant checks, G7.7's out-of-tree sandbox definition and G7.8's
footprint grammar have landed. An agent told a guard is absent plans work that the
guard will refuse mid-task, and the refusal arrives as an unexplained failure. Go
row by row: name what enforces it now, name the commit or issue that closed it,
and keep the honest **Nothing** where it is still true. Check each claim against
the code before you rewrite it — that table's value is that it has never lied in
the optimistic direction, and it must not start now.

### The suite: `tests/test-brief-contract.sh`

New file, yours. It must assert against the tools themselves, never against a
hand-maintained list — a hand list rots exactly the way the prose it checks does.

1. **Verbs and flags.** Extract every `tp …`, `tp-task …`, `{{TASK_CLI}} …` and
   `{{TASK_CLI_NAME}} …` invocation from `AGENTS.md` and the three templates,
   from fenced blocks and from inline code alike. Resolve the placeholder spelling
   to the real tool. Assert each verb is one `bin/tp` dispatches and
   `libexec/tp-task` / `libexec/tp-pump` accept, and each long flag is one the
   tool's own parser arms name. Derive both sets by reading the tools' dispatch
   and parse arms at run time.
2. **States.** Extract every ledger status the four documents name — `open`,
   `in_progress`, `done`, `blocked`, `needs-review`, `stuck`, whatever else
   appears — and assert each is in `docs/LEDGER-CONTRACT.md` §4's status
   vocabulary. A document naming a state the contract does not define is the same
   defect one level up.
3. **Placeholders.** Extract every `{{NAME}}` from the three templates and assert
   the renderer fills it: `lib/pump-lib.sh`'s `apl_render_template`, fed by
   `libexec/tp-pump`'s `render_brief_stream` and the resume-note path. The
   assertion that matters is that **no `{{` survives** a render of a fixture task
   — an unfilled placeholder reaches the agent as literal braces and it has no way
   to know what was meant. Assert the converse too where it is cheap: a
   placeholder the renderer fills but no template uses is dead machinery worth
   naming in your completion note.
4. **The end-to-end case, which is the suite's point.** Render a brief for a
   fixture task, then run a stub agent that follows *only* the brief's numbered
   steps — claim, `heartbeat --start`, a commit, `heartbeat --end`, `complete`
   — with no access to the source tree's tools beyond what the brief names.
   Assert the fixture ledger ends with the task `done` and `claimed_by` cleared.
   This is the case that fails the day a step in the brief stops being executable
   in the order the brief gives it.

Refusals matter as much as verbs: where `AGENTS.md` tells an agent what a tool
will refuse (`complete` on a review task, `release` on anything but
`in_progress`), assert the refusal actually happens and that the exit status is
the one the document implies.

Hermeticity: `tests/run-all.sh` discovers `tests/test-*.sh` by glob, so
registration is automatic, but it also fails the run if a suite litters the repo
root or rewrites a run-state file. Work in `mktemp -d`, source
`tests/suite-prologue.sh` like every other suite, and clean up on `EXIT`.

### A hazard before you edit a template

`tests/golden/brief-f55.txt`, `brief-f57.txt`, `resume-note-f79.txt` and
`consumer-resume-template.md` pin the rendered bytes, and they belong to G8.1, not
to you. Read them first. Prefer corrections that do not change rendered output. If
a correction genuinely must change what the brief says to an agent, land it and
record the golden update as debt in your completion note naming the exact golden
files — do not edit them, and do not weaken an assertion to make a suite pass.

## Scope

Yours: `AGENTS.md`, the three templates, `templates/README.md`, and the new
suite. Nothing enforces that list but you.

This task **asserts**; it does not fix tools. When the suite finds a mismatch the
default repair is in the document, because the tools are what actually runs. If
you find a mismatch where the *tool* is wrong — a verb `bin/tp` advertises and
does not dispatch, a placeholder the renderer drops — stop, file it as an issue,
record it in your completion note, and leave `bin/`, `lib/`, `libexec/`, `gates/`
and every other suite untouched. G10.3 is editing the argument parsers of eleven
tools in the wave after yours; a stray edit there collides with it.

`templates/README.md` is yours and is where the rule itself gets written down, so
that the next person editing a template knows a suite is watching.
