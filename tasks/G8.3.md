# G8.3 — The brief states the budget, the mode and the sandbox it actually got

## Spec

G8.1 made the brief's untrusted text safe to read. This task makes the brief's own
text true. Three claims it currently gets wrong, all for the same reason — the
renderer has no key for the fact, so the template either says nothing or says
something false:

- The agent is launched under a turn budget it is never told, and both shipped briefs
  were rewritten to *forbid* naming a budget at all because there is no placeholder
  for one (**#136**).
- `{{BASE}}` means a human-reviewed branch in one mode and an auto-merged buffer in
  the other, and no key tells the template which — so the briefs were weakened to a
  bare prohibition that is true in both and informative in neither (**#137**).
- Every brief promises the primary checkout is mounted read-only and an absolute-path
  write will fail, which is false under `runners/local` (no container at all) and
  false under the docker runner in the single-repo shape where the read-only primary
  and read-write ledger mounts collapse into one read-write mount (**#92**).

They are one task because they are one edit to the same two `TPL_VARS` maps, the same
placeholder table in `templates/README.md`, and the same pair of shipped templates.
Read all three issues; **their line citations have drifted** and are starting points,
not coordinates — re-derive by symbol name (`render_brief`, `render_brief_stream`,
`write_resume_note`, `launch_unit`, `integrate_one_unit_real`).

### The two maps, and the one constraint on how you branch

The brief map is in `render_brief`/`render_brief_stream` (cited
`libexec/tp-pump:1518-1531`); the resume map is in `write_resume_note` (cited
`:1574-1587`).

**You do not own `lib/pump-lib.sh`.** The renderer has no inverted section —
`{{^KEY}}` is not a form it knows, and `templates/README.md` already documents that
and describes how badly it fails when a template tries it. **G6.9** rewrote the
renderer for `&` and unclosed markers and did not add one. So a mode that must produce
one sentence in one case and a different sentence in the other is expressed as **two
mutually exclusive keys**, each set only in its own case, each wrapped in its own
`{{#KEY}}` section. Do not add an inverted section to the renderer to avoid this.

### #136 — `{{TURNS}}`

Neither map carries the granted budget. The value is already in scope at the right
moment: `launch_unit` computes it (cited `:1704-1705`)

```sh
local turns="$MAX_TURNS"
[[ "$GRAIN" == "task" ]] && turns="$TASK_MAX_TURNS"
```

44 lines before it calls `render_brief`, and forwards the same value to the runner as
`TP_MAX_TURNS`/`MAX_TURNS` (cited `:1788`). **Pass it in** rather than re-deriving it
at the render site, so the number in the brief can never disagree with the number the
runner receives. The standalone `--render-brief` path does not go through
`launch_unit`, so it must resolve the same grain choice itself — that is the one place
a divergence can be introduced and the test below pins it.

Then repair the workaround. `templates/task-brief.md` says "Pass no `--turns`. The
budget is the supervisor's to set…" and `templates/README.md` (cited `:245-257`)
states the prohibition as a rule of template authorship, attributing the gap to
**#90**. #90 is the *authorization* half — `cmd_claim` rewriting
`turn_budget_remaining` and zeroing `consecutive_failed_iterations` on every call —
and **G7.5** has already closed it. A brief may now **state** the budget; it still
must not **pass** `--turns` on `claim`. Keep that warning, drop "There is no
`{{TURNS}}` placeholder", and have both briefs say what to do as the budget runs down:
land the increment, `heartbeat --end`, then one of the three endings.

### #137 — which integration mode produced this base ref

`BASE_REF` is reassigned to the auto-trunk under `--integration-trunk` (cited
`:461-462`, guarded by `INTEGRATION -eq 1 && BASE_GIVEN -eq 0`), and in that mode the
pump itself runs `git merge --no-ff` of every agent branch into the trunk **every
tick**, gated only by the build gate — `integrate_one_unit_real` (cited `:1955-1982`)
called from `reconcile_trunk` (cited `:1990-1997`) wired into `do_tick`. No human, no
PR. `graduate_trunk` (cited `:2006`) is the single trunk → `INTEGRATION_BASE` PR.

Add to both maps a mutually exclusive pair — `[TRUNK_MODE]` set only under
`--integration-trunk`, `[PR_MODE]` set only otherwise — plus the scalar
`[INTEGRATION_BASE]`. Then restore the strong, accurate sentence in each mode:

- under `PR_MODE`: the only way this branch reaches `{{BASE}}` is a human merging your
  draft PR;
- under `TRUNK_MODE`: the supervisor merges this branch into `{{BASE}}` once your
  build gate is green, and a human reviews `{{BASE}}` → `{{INTEGRATION_BASE}}` later.

An agent needs the second sentence to reason about what happens to an unfinished
series after it stops. `templates/README.md` (cited `:112` and `:234-243`) currently
*prescribes* leaving the graduation mechanism unnamed and records the trap; rewrite
both passages to "say it per mode, with `{{#TRUNK_MODE}}`", and re-derive their stale
`libexec/tp-pump` citations while you are in there.

`{{BASE}}`'s own value must not change in either mode, so no existing consumer
template changes meaning.

### #92 — the read-only-primary promise becomes a rendered fact

The sentence sits outside any `{{#…}}` section in both briefs (cited
`templates/task-brief.md:76-80`, `templates/phase-drain-brief.md:76-77`), and no key
in either map is runner-dependent. Under `runners/local` there is no container: the
runner's own header says so — "IT DOES NOT SANDBOX ANYTHING … no read-only primary
checkout … Every guarantee in docs/RUNNERS.md §4 belongs to the claude-docker runner
and none of them apply here". Under the docker runner in the single-repo shape,
`runners/claude-docker/runner.sh` (cited `:261`) collapses to
`-v "$ledger_repo":"$ledger_repo"` with no `:ro` when `ledger_repo == repo_root`, and
`docs/RUNNERS.md` already concedes the guarantee does not hold for that run.

The harm is a prompt-truth defect, not a capability: a false guardrail claim removes
caution the model would otherwise apply to absolute paths, against the very tree every
sibling worktree is cut from.

Make the runner able to say what it provides. Add a **`capabilities` verb** to the
runner contract, in the shape `list` already established in **G3.1**: it takes no
per-launch environment, prints one guarantee name per line, exits 0, and an empty
capability set is exit 0 with no output. `runners/local/runner.sh` prints nothing for
`readonly-primary`. `runners/claude-docker/runner.sh` prints it **only** when the
mounts do not collapse — the same `ledger_repo == repo_root` test that decides the
mount. Bump `CONTRACT_VERSION` from 2 to 3 in both runners and document the verb, the
empty case and the failure case in `docs/RUNNERS.md` beside §1.3's `list` spec, plus
which shape provides which guarantee.

The pump queries it and sets `[SANDBOX_READONLY_PRIMARY]` or, mutually exclusively,
`[SANDBOX_NO_READONLY_PRIMARY]`. A runner that does not answer the verb — an older
contract-v2 runner — is treated as **not** providing the guarantee: the safe default
is the sentence that tells the agent nothing will catch its mistake. The negative
branch must say the opposite in as many words: nothing prevents an absolute-path write,
so do not make one, and a mistake will land on the primary every sibling worktree is
cut from.

## Scope

The ten paths in `files:` above and nothing else. Nothing enforces the list but you.

Do not touch:

- **`lib/pump-lib.sh`** — see the constraint above. The two-mutually-exclusive-keys
  shape exists precisely so this task needs no renderer change.
- **`runners/claude-docker/entrypoint.sh`** — **G8.1**'s. `tests/test-entrypoint.sh`
  *is* yours (its placeholder-set assertions are the thing that catches an
  undocumented key), but the entrypoint itself is not. If the capability answer needs
  something in-container, it is designed wrong: `capabilities` is answered by the
  runner on the host, before launch.
- **The fence, the sanitiser and the untrusted maps** — **G8.1**, landed before you.
  Your new keys are operator- and supervisor-derived facts, so they belong in the
  **trusted** `TPL_VARS` map. Do not route them through `apl_display_data`.
- **Provenance holds and the `held` reporting** — **G8.4**, which runs after you in
  the same `libexec/tp-pump`. Leave the plan and `--list` output easy to extend.
- **`docs/CONFIG.md`.** #136 asks for a note on the `TASKPUMP_MAX_TURNS` /
  `TASKPUMP_TASK_MAX_TURNS` rows that the value is now visible to the agent. That file
  belongs to **G8.5**; write the note into your completion notes as doc debt.

`taskpump.conf.example` and `CHANGELOG.md` are also G8.5's. The CHANGELOG entry is
