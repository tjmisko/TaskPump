# G7.9 — The unattended-drain-safe drill

## Spec

This task is the phase's promise made executable. The plan's `safe_to_self_drain_after`
field names **G7.9**, and specifically names the moment this drill goes green, as the point
the operator may stop watching the pump. Every task before you in G7 argued that some door
is now closed. You are the reason the operator does not have to take that on trust. **When
this task is done, the operator may walk away.** Write it so that is true.

There are no GitHub issues attached. Your inputs are the eight completed siblings, their
completion notes, and the five claims below. Read all eight notes before you start — several
of them hand you documentation debt they were not allowed to land.

### The two suites

**`tests/test-hostile-conf.sh`**, driven by a cloned repository built to attack the operator,
in `tests/fixtures/hostile-repo`. That fixture is a git repository whose checked-in files are
the attack: it is the shape a consumer gets by cloning something they did not write. Every
vector must be refused **by name** — the diagnostic must say what it refused and why, not
merely fail:

- a `taskpump.conf` containing a command (from G7.1: the conf is parsed, the command never
  runs, and `tp task --help` still exits 0);
- a `taskpump.conf` assigning `PATH` — the variant that survives a naive key=value parser,
  because `set -a` exports it and re-points `git`, `jq`, `yq` and `docker`;
- a `taskpump.conf` planted above the worktree, outside any repository, that the walk must
  no longer reach;
- a `TASKPUMP_TASKS_DIR` that escapes the workspace by `..`, and a `tasks` symlink out of the
  tree;
- a repo-carried pre-flight hook, i.e. `TASKPUMP_PRE_FLIGHT` resolving inside the workspace
  (from G7.7: exit 75, named);
- a repo-carried `claude-settings-auto.json` widening the agent's permissions;
- a repo-supplied build gate — an executable `smoke_test.sh` and a `Cargo.toml`, neither of
  which the pump may run when no gate is configured (from G7.3).

**`tests/test-ledger-forgery.sh`**, driven by a ledger fixture with two branches in play. An
agent branch must not be able to:

- complete, block or release a sibling's task (G7.2);
- block a task that is already `done` (G7.2);
- approve the review of work it implemented, with or without holding the gate (G7.6);
- land a hand-edited frontmatter change on the back of an unrelated verb's commit, and a
  drifted ledger must be reported at exit 3 (G7.6);
- raise its own turn budget above the supervisor's grant, or zero its own failure count by
  re-claiming (G7.5).

And the runaway case, which is the one the whole milestone turns on: **a stubbed agent that
burns its budget landing nothing is parked by `scrub` within the granted turns.** Drive the
entrypoint's per-session cycle — claim, `heartbeat --start`, `heartbeat --end`, no commits —
for more rounds than the granted budget and assert the task ends `needs-review` or `stuck`
rather than `in_progress`. Before G7.5 this ran forever with the budget pinned at 2 and the
failure count pinned at 1. Assert the counters accumulate, not just the final status: a test
that only reads the end state would pass again the day someone re-pins the counters at a
different value.

Both suites go into `tests/run-all.sh`. A drill that is not in the runner is a drill nobody
runs.

### The record

`SECURITY.md` and `docs/THREAT-MODEL.md` must say which tier this moves and which it does
not. This phase makes an operator's own repository safe to drain unattended. It does **not**
make an untrusted repository or a PR stream safe — that is the Tier 3 posture, and
`docs/THREAT-MODEL.md` §5 names the remaining preconditions. Say so plainly; the failure mode
here is a document that reads like a clean bill of health.

Record the residual hazards that survive this boundary, with the throttle each implies. The
plan states three and the operator needs all three in writing, because "walk away" is
conditional on them:

1. A disk-panic cap of `0` is ignored until G9.2, because `apl_read_cap` rejects `0` as a
   value. Keep `--jobs` at 3 or below through G8 and watch free space — the watchdog will
   write a cap it cannot enforce.
2. The pump's deadlock detector reads the plan rather than the outcome until G10.1, so a
   runner that fails every launch still looks healthy. A phase that has been LAUNCHING the
   same unit across many ticks is a manual check.
3. The ledger has no provenance dimension until G8.4. During G8 the drain is safe only
   because the ledger is written by the operator and by agents already bounded by G7.2's
   claimant checks. Do not point this pump at a PR stream before G8.4 and G11.2 are both
   green.

### The doc debt

You own `CHANGELOG.md` and `taskpump.conf.example` for this phase, and every sibling was
told to record its debt for those two files rather than touching them. Collect all eight
completion notes and land every item that falls inside your footprint. `README.md` is yours
too: the adoption walkthrough and any quickstart text that describes the old conf semantics,
the old build-gate default or the old mount shape must stop being false.

The CHANGELOG entry for v0.3.0 is substantial and it is a MINOR release: the conf is parsed
rather than sourced when discovered (with `TASKPUMP_CONFIG` as the escape hatch), the
discovery walk is bounded and ownership-checked, conf-relative paths are contained, the
build gate no longer defaults to cargo and `smoke_test.sh`, an image without a build command
is refused, submodule init is opt-in, an unrunnable gate or hook aborts at startup,
`heartbeat` gains a required argument, a same-branch re-claim no longer resets the budget or
the failure streak, the closing verbs authenticate their caller, `block` refuses a `done`
task, the implementer cannot sign its own review, `fsck --drift` exists, the `files:` grammar
is defined and enforced, the runner mounts a credential projection instead of `~/.claude`,
and agent policy resolves from an operator-owned root. Consumers will notice all of it.

## Scope

The declared `files:` list is `tests/test-hostile-conf.sh`, `tests/test-ledger-forgery.sh`,
`tests/fixtures/hostile-repo`, `tests/run-all.sh`, `SECURITY.md`, `docs/THREAT-MODEL.md`,
`taskpump.conf.example`, `CHANGELOG.md` and `README.md`. Nothing enforces that list but you.
Nothing is scheduled beside you — this is the phase tail.

**You may not fix what the drill finds by editing the tool.** No file under `lib/`,
`libexec/`, `runners/`, `hooks/` or `gates/` is in your footprint. If a vector is not
refused, that is a defect in a sibling's landed work: write the failing assertion, then open
a GitHub issue and a follow-on task naming the file and the vector, and say so in your
completion note. A drill that was quietly weakened until it passed is worth less than no
drill, and the operator is going to walk away on this result.

`tests/fixtures/hostile-repo` is a new directory and it is the one place in this ledger that
declares a directory footprint. G7.8's contract note is what makes that safe — read it.
Nothing inside that fixture may be executable-by-accident on a developer's machine: it exists
to be pointed at, and the suites must run it under a scratch `HOME` and a scratch state
directory so a leaked payload cannot touch the real ones.

Debt you cannot land — `docs/CONFIG.md` rows, `docs/PUMP-MECHANISMS.md` sections, brief
template sentences — stays outside your footprint. Itemise it in your completion note and
create a follow-on task naming the files, rather than widening.
