# G3.3 — Ship a runners/local process runner

## Spec

The runner that makes "any repository" true without a container runtime.
`runners/local/runner.sh`:

- `launch`: start the agent command (`TASKPUMP_LOCAL_AGENT_CMD`, required —
  there is no sane default agent) in its own session via `setsid`, redirect
  output to the workspace's agent log, record `<name> <pgid>` in a registry
  file under the state dir, print the name as the handle, detach.
- `stop <name>`: signal the recorded pgid (TERM, then KILL after a grace
  period). Both "already gone" shapes from RUNNERS.md §1.2 — never recorded,
  and recorded but dead — are success; registry entry is removed either way.
- `list`: print registry names whose pgid is still alive; prune dead entries
  while there.
- Sandboxing is explicitly NOT this runner's job — one prominent doc paragraph:
  agents run with the caller's full host permissions; the container runner is
  the hardened one.

Requires G3.2's runner-backed liveness to be useful under the pump — with a v1
pump this runner's agents would be invisible.

## Scope

The new runner, its suite, RUNNERS.md §3 (replace the sketch with the real
thing, keeping the "about fifteen lines" claim honest or amending it).

## Acceptance

- A hermetic suite drives launch/stop/list with a `sleep`-based stub agent:
  handle printed, log written, stop tolerates both already-gone shapes, list
  reflects reality after kills, registry never accumulates dead entries.
- An end-to-end `tp pump --once` in a fixture repo with the local runner and a
  stub agent completes a tick with liveness working (no docker anywhere).
- RUNNERS.md documents the runner and its non-sandboxing loudly.

- Non-sandboxing is stated in the file header, in --help, and in RUNNERS.md
  §3.1 on its own.
- docs/RUNNERS.md §3 rewritten: the sketch is replaced by the real runner
  (config, registry, the two load-bearing details), and the skeleton survives as
  §3.4 for someone adapting to something else.

Two findings from actually running it
1. `kill -0` is the wrong liveness test. It succeeds on a ZOMBIE, and an agent
   whose parent (this short-lived runner) has exited is reparented to PID 1 —
   which in any minimal container never reaps. My first implementation reported
   a dead agent as live forever: stop could not finish, list could not prune,
   the phase would never relaunch. Liveness now reads process state via ps and
   treats Z as gone (kill -0 remains the fallback where ps is absent). The suite
   constructs the zombie case deliberately.
2. The pump's launch prerequisites are container-shaped. A local-runner consumer
   must still set TASKPUMP_IMAGE to a non-empty placeholder and
   TASKPUMP_IMAGE_BUILD='' (unset means "docker build the repo root"). Nothing
   here can fix that without changing the pump's prerequisite block, which is
   not this task; documented loudly in RUNNERS.md §3.3 and worth its own task.

Verification (tests/test-tp-runner-local.sh, 37 assertions, offline)
- Lifecycle with sleep-based stub agents: handle, registry entry, own process
  group, workspace log, list with one and two agents.
- An agent killed behind the runner's back drops out of list AND its entry is
  pruned (the zombie case), registry never accumulates.
- stop across both already-gone shapes, idempotent on repeat, removes the entry;
  a live agent's whole group dies (the stub spawns a child, so this is real).
- Empty fleet is zero bytes and exit 0; a missing registry is an empty fleet; an
  unreadable one is non-zero with one line (root-skipped).
- Refusals: no agent command, no workspace, no name, and a duplicate launch over
  a live name.
- End-to-end: a real `tp-pump --once` in a git fixture with
  TASKPUMP_DOCKER pointed at a nonexistent path — the tick launches a real
  agent, and a second tick does not relaunch it while a --dry-run plan of the
  same state reports RUNNING. Liveness is coming from `list` (G3.2); there is no
  container runtime in that test at all.
  The fixture COPIES the tools into itself: tp-pump derives the repo it drives
  from its own resolved location (readlink -f defeats symlinking), so the first
  version of this test cut a real feat/f80 branch and worktree in TaskPump's own
  repo. Cleaned up; the committed test is hermetic.
