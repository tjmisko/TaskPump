# G11.1 — The foreign-repo drain runs on a host that is not this one

## Spec

G9.6 proved that a foreign consumer repository drains: a non-Rust scratch repo
with a relocated tasks subdir, a non-`.md` extension, no `~/.claude`, no image and
a stub agent goes `tp init` → `tp task create` → `tp task ready` →
`tp pump --dry-run` → a completed two-phase task-grain drain. It proved it on this
host — GNU coreutils, `docker`, `cargo` and `wezterm` all present, which is the
one host whose absence the whole G9 phase was about. Eleven of G9's fourteen
issues were a wrong default or a GNU-only flag inside one of four files, and every
one of those fixes is currently asserted by a suite that would pass just as
happily if the fix were reverted, because the host supplies what the code assumes.

After this task the drain runs on every push against a deliberately hostile
environment, and a regression to `stat -c`, `date -d`, `df --output`, `du -b`, a
hardcoded `docker`, or a `cargo`/`wezterm` assumption fails the build instead of
surfacing at somebody's adoption.

### The environment the job must build

- **Non-GNU coreutils behaviour.** Put a shim directory at the front of `PATH`
  holding `df`, `stat`, `date` and `du` that accept only the BSD spellings and
  **fail loudly** on the GNU-only ones (`stat -c`, `date -d`, `df --output`/`-B`,
  `du -b`). Failing loudly is the whole mechanism: a shim that quietly tolerates
  GNU syntax detects nothing. Each shim's refusal must name the flag it rejected,
  so a failure in CI reads as "tp-disk-watchdog called `stat -c`" rather than as a
  broken test.
- **No `cargo`, no `wezterm`.** Scrub both from `PATH` and assert with a probe at
  the top of the job that neither resolves — an assertion, not an assumption, so a
  future runner image that ships cargo cannot silently weaken the job.
- **`podman` instead of `docker`.** Point `TASKPUMP_DOCKER` at podman and assert
  the container work actually went through the binary named by that variable —
  route it via a logging wrapper and assert the log is non-empty. If the runner
  image cannot provide podman, the job **fails**; it must never fall back to
  `docker`, because a silent fallback turns this job into a second copy of the
  suite that already passes.
- **Both runners.** Run the G9.6 drain to completion under `runners/claude-docker`
  (through podman) and under `runners/local`. They fail differently, and the local
  runner is the one a first adopter reaches for.

### False green is the failure mode to design against

A CI job that skips its assertions reports the same colour as one that passes
them. Make skipping impossible to mistake for success: `tests/test-generic-consumer.sh`
prints its assertion count, the job asserts that count is non-zero and at least
what the suite is known to contain, and any environment precondition the suite
cannot meet is a hard failure rather than an early `exit 0`. If the suite already
has a skip path from G9.6, convert it.

Keep the suite runnable on a developer's machine too: the BSD-shim environment
should be something the suite enters when asked (an env switch or a flag), not
something a plain `./tests/test-generic-consumer.sh` cannot do without CI. A
portability suite nobody can run locally gets disabled the first time it goes red.

`tests/fixtures/foreign-consumer` is a directory in your footprint, and after
G7.8 a declared directory is protected by path containment, so the shims and any
new fixture material belong under it.

Making the job **required** on push has two halves: the workflow triggering on
push, which is yours, and the branch-protection setting that marks the check
required, which is a repository setting no task file can change. Do the first and
record the second in your completion note addressed to the operator.

## Scope

Three paths: `tests/test-generic-consumer.sh`, `.github/workflows/ci.yml` and
`tests/fixtures/foreign-consumer`. Nothing enforces that but you.

**Two siblings are running beside you right now.** G11.2 owns
`tests/run-all.sh`, `tests/fixtures/hostile-*`, `docs/THREAT-MODEL.md` and
`SECURITY.md`; G11.3 owns `README.md`, `docs/RUNBOOK.md`, `docs/CONFIG.md` and
`tests/test-docs-claims.sh`. `ci.yml` is yours alone in this wave — G6.7, G6.10
and G9.6 each edited it earlier, so read what they left before adding a job, and
extend rather than restructure.

If the hostile environment exposes a portability defect in `lib/`, `libexec/`,
`gates/`, `hooks/` or `runners/` — and it may well, since nothing has ever run
them this way — **do not fix it here**. Those files belong to G9's tasks, which
have landed. File an issue, name it in your completion note, and if it blocks the
job from going green, mark the specific case as a known failure with the issue
number rather than deleting the assertion or widening your footprint.

## Acceptance

- [ ] A CI job in `.github/workflows/ci.yml` triggers on push, builds the
      consumer repository from scratch, and runs the G9.6 drain to completion.
- [ ] The job shims `df`, `stat`, `date` and `du` to BSD behaviour, and each shim
      fails naming the GNU-only flag it was given.
- [ ] The job asserts `cargo` and `wezterm` do not resolve on `PATH` before the
      drain starts.
- [ ] `TASKPUMP_DOCKER` points at podman, the job asserts the named binary was the
      one actually invoked, and an unavailable podman fails the job rather than
      falling back to `docker`.
- [ ] The drain completes under both `runners/claude-docker` and `runners/local`,
      each asserted separately.
- [ ] `tests/test-generic-consumer.sh` prints an assertion count; the job fails if
      it is zero or below the known floor; no precondition results in a silent
      skip.
- [ ] The BSD-shim environment is enterable locally by an env switch or flag, and
      that is documented in the suite's header comment.
- [ ] Mutation check, recorded in the completion note: reintroducing one GNU-only
      call in a tool makes exactly this job fail, and the failure text names the
      tool and the flag.
- [ ] Completion note records the branch-protection step the operator must take to
      mark the check required, and any portability defect found and filed.
