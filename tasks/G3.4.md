# G3.4 — Reject branch names that cannot round-trip the slug

## Spec

The slug map (`/` → `-`) is lossy for branches with more than one `/`, which
breaks the name→branch reverse mapping liveness and resume depend on
(RUNNERS.md §2). Close it by validation, not by a cleverer encoding:

- `tp task claim --branch` rejects a branch whose name contains more than one
  `/` (or any character the slug cannot represent distinctly), with a message
  stating the constraint and the reason (the container-name round-trip).
- The pump's own branch construction (`TASKPUMP_BRANCH_PREFIX` + phase) is
  validated once at startup so a misconfigured prefix fails the run loudly at
  tick zero, not per-launch.
- RUNNERS.md §2 documents the constraint as enforced rather than advisory.

## Scope

Validation and docs. Do NOT change the slug encoding itself — existing
container names on operators' hosts must keep matching.

## Acceptance

- Claim with `feat/a/b` fails with the constraint message; `feat/a` passes
  (asserted in the task suite).
- Pump startup with `TASKPUMP_BRANCH_PREFIX=x/y/` exits with a config error
  naming the key.
- CHANGELOG notes the previously-silent breakage now fails loudly.
