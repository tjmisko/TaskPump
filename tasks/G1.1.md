# G1.1 — Audit arachne.conf to pin every default the G1 flips will change

## Spec

G1.3–G1.7 will flip every Arachne-shaped baked-in default to a neutral spelling.
Before any flip lands, `examples/arachne.conf` must pin the *current* value of
every key those flips will touch, so the reference consumer is shielded by
configuration alone and each flip is provably behavior-preserving under the conf.

Sweep every `${TASKPUMP_X:-...}` fallback in `libexec/tp-*`, `lib/*.sh`,
`runners/claude-docker/{runner.sh,entrypoint.sh}`, `gates/*`, and `hooks/*`
whose default mentions arachne (name, filename, identity, prefix, or path), and
cross-check against the census in `taskpump.conf.example`. Known-unpinned today:
`TASKPUMP_WORKSPACE_TASK_CLI`, `TASKPUMP_COMMITTER_NAME`/`_EMAIL`,
`TASKPUMP_PROG_NAME`, the agent-log/brief/goal-note/resume-note/ro-probe names,
the pool-cap/usage-reset/watchdog-log names, and the monitor notes dirname and
cache base. The `# (default)` markers in arachne.conf change meaning after the
flips — from "redundant, kept for the prose" to "load-bearing pin" — so the
file's header comment must say so.

## Scope

Only `examples/arachne.conf` and `taskpump.conf.example` change. No tool
behavior changes in this task. The hardcoded lockfile name in `tp-task`
(`.arachne-task.lock`, no key today) is G1.3's problem — note it there, don't
solve it here.

## Acceptance

- Every key that G1.3–G1.7 names in its Spec appears in `examples/arachne.conf`
  set to today's shipped default.
- The completion notes record the audit command(s) used and paste the final
  "unpinned arachne-flavored defaults" list, which must be empty except for
  defaults that have no config key yet (each of those must be named in the Spec
  of the G1 task that will add the key).
- `./tests/run-all.sh` stays green (nothing behavioral moved).
