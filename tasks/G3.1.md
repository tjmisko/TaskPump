# G3.1 — Add the runner.sh list verb to the runner contract

## Spec

The v2 addition RUNNERS.md §1.3 promises. Contract:

- `runner.sh list` prints the name of every live agent this runner knows about,
  one per line, and exits 0. An empty list is exit 0 with no output.
- It reads only the configuration `stop` already reads (no per-launch env) —
  the pump calls it once per tick with no task in hand.
- Names printed must be the same names `launch` created (`<prefix><slug>`), so
  existing name→branch mapping keeps working.
- Failure to enumerate (runtime unreachable) exits non-zero with one line on
  stderr — the caller decides the fallback, the runner never guesses.

Implement in `runners/claude-docker/runner.sh` via the existing
`docker ps --filter name=<prefix>` machinery (share the code path with
`lib/pump-lib.sh`'s enumeration rather than duplicating the filter). Rewrite
RUNNERS.md §1.3: liveness is askable in v2; the prefix-scrape remains the
documented fallback and the naming contract stays mandatory.

## Scope

Contract text, reference implementation, tests. The *pump* does not start
calling `list` here — that is G3.2, so this lands independently verifiable.

## Acceptance

- `tests/test-tp-runner-stop.sh` (or a sibling suite) drives `list` against a
  stubbed docker: populated, empty, and unreachable-runtime cases, asserting
  the exit codes and output shape above.
- RUNNERS.md documents the verb, the empty-list case, and the failure case.
- Version note: MINOR bump material, recorded in CHANGELOG Unreleased.
