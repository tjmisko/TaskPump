# G1.2 — Re-anchor the Arachne-equivalence suites to explicit pins

## Spec

`tests/test-golden-plan.sh` currently promises "with NO taskpump.conf, an
Arachne-shaped repo behaves identically to the pre-extraction tools". The G1
flips deliberately break that promise, so re-anchor it first: the golden fixture
loads the reference pins (source `examples/arachne.conf` into the fixture's env,
or write it as the fixture repo's `taskpump.conf`) and the promise becomes
"with the reference conf, behavior is byte-identical". This must land while the
pins still equal the defaults, so the re-anchored suite passes before any flip
and every flip can be validated against it.

Also invert the default-pinning assertions that would otherwise contradict the
flips: `tests/test-tp-task-generic.sh` pins the bare diagnostic prefix to the
historical `arachne-task:` spelling (~line 275) — split it into a conf-pinned
Arachne assertion and a bare-default assertion that G1.4 will update in the same
commit as its flip. Audit the other suites for bare-default reliance the same
way (`test-tp-monitor.sh`, `test-tp-pump.sh`, `test-entrypoint.sh` lean on
`.arachne-*` spellings heavily; anything asserting a *default* rather than a
pinned value gets pinned or labeled).

Golden files under `tests/golden/` that embed tool-emitted spellings (e.g.
`plan-frontier.txt`'s `arachne-pump plan` header) stay as-is for now — they are
generated under the pinned env after this task, and G1.4/G1.5 regenerate them
when the emitting default flips.

## Scope

Test and fixture changes only. No tool source changes.

## Acceptance

- `./tests/run-all.sh` is green with zero source changes.
- The golden suite's equivalence claim is exercised through explicit pins:
  deleting any single arachne-flavored default from the *pins* makes it fail;
  the shipped default no longer participates.
- Every remaining bare-default assertion in the suites is either pinned or
  carries a comment naming the G1 task that flips it.
