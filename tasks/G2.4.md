# G2.4 — Zero shellcheck warnings, then ratchet CI to -S warning

## Spec

ci.yml's shellcheck job pins `-S error` and says why: at extraction there were
38 pre-existing warning-level findings, and a red CI everybody ignores is worse
than no CI. Its stated intended path is to ratchet — clear the warnings, then
change `-S error` to `-S warning` and never let it back down. The drain grew
the count to 59. This task walks that path to zero and flips the ratchet.

The census below was taken at 3227bef with `koalaman/shellcheck:stable`
(docker), CI's exact file list and flags plus `-S warning`:

    find bin libexec lib gates runners hooks \
      -type f \( -name '*.sh' -o -perm -u+x \) | sort
    shellcheck -S warning -x <files>

59 findings, 10 distinct codes, grouped here into buckets. One commit per
bucket (conventional `refactor:`/`fix:`/`style:` as fits); full suite between
buckets.

### Bucket A — SC1007 x26: the `CDPATH= cd` idiom (mechanical)

Every instance is the deliberate empty-prefix `CDPATH= cd -- ...` guard.
Replace with `CDPATH='' cd -- ...` — byte-identical semantics, warning gone.
Sites: bin/tp:11; gates/claude-token-fresh:31; gates/claude-usage:56,61,62;
gates/disk-low:24; gates/net-health:30; hooks/fs-guard:27;
hooks/gitignore-repair:27; lib/config.sh:61,62,106; libexec/tp-agent-watchdog:32,39;
libexec/tp-cleanup:43,52; libexec/tp-dag-render:65; libexec/tp-disk-watchdog:40,49;
libexec/tp-monitor:110; libexec/tp-pump:58,63,64; libexec/tp-stream-fmt:16;
libexec/tp-task:32,68.

### Bucket B — SC2097/SC2098 x16: the launch env block (tp-pump:971–984)

The runner launch passes `LEGACY="$LEGACY"` pairs (canonical TP_* name plus
legacy name) into the child env. Intent is "forward to the child", which
shellcheck reads as a self-assignment confusion. Fix: prefix the invocation
with `env` (`cid=$( env TP_WORKSPACE=... ... "$RUNNER" launch )`) so the
assignments are env's arguments, not shell prefixes. Behavior identical
($RUNNER is an absolute path; PATH not consulted). Both codes vanish.
Verify the launch path with the suite's NO_LAUNCH goldens plus
test-tp-runner-stop; nothing in the dry-run goldens touches this line.

### Bucket C — SC2034 x8: "unused" variables (mixed — three sub-cases)

1. NOT dead, consumed by name across a source boundary; annotate with
   `# shellcheck disable=SC2034` + a comment naming the consumer:
   - tp-pump:797 `TPL_VARS`, :811 `TPL_BLOCKS` — read by `apl_render_template`
     (lib/pump-lib.sh) via indirection.
   - tp-monitor:1170 `L`, :1171 `R` — passed BY NAME to `compose_columns "$W" L R`
     (nameref inside).
2. Throwaway read fields; rename to `_`:
   - tp-monitor:218 `brief` (`read -r name branch brief task _rest`)
   - tp-monitor:1035 `j` (trailing field)
3. Investigate, then delete or wire:
   - tp-monitor:655 `ceiling="${_pf[4]:-}"` — parsed from the pump state file
     but never rendered. Either the monitor should display the ceiling (small
     feature, check the state-file schema) or the assignment goes.
   - tp-agent-watchdog:39 `REPO_ROOT` — line 32 already computes
     `_tp_self_root` and sources config; check whether sourced pump-lib reads
     REPO_ROOT (rg lib/pump-lib.sh). If nothing does, delete the line
     (it also carries one of Bucket A's SC1007s).

### Bucket D — SC2206 x3: unquoted array expansion (tp-monitor:1328,1337,1341)

`local -a arr=(${GLAYERS[$lay]})` deliberately splits a space-joined id list.
Ids can't glob today, but the robust form costs nothing:
`local -a arr; read -r -a arr <<< "${GLAYERS[$lay]}"`.

### Bucket E — SC2155 x2: declare-and-assign masking (tp-pump:766,1467)

`local out="$(...)"` masks the substitution's exit status. Split into
`local out; out=...`. Cosmetic under `set -uo pipefail` (no -e), but the
split form is the house style elsewhere in the file.

### Bucket F — SC2318 x1: REAL latent bug (tp-monitor:1593)

`local width="$1" n l1 l2 cut=$(( width - 4 ))` — all words expand BEFORE
`local` assigns, so `cut` computes from the caller-scope `width` (empty → 0 →
cut=-4, or a stale leaked global), not from `$1`. Split:
`local width="$1" n l1 l2; local cut=$(( width - 4 ))`. Check call sites for
a leaked global `width` that has been masking this; add a rendering test at a
narrow width if the -4 case is reachable.

### Bucket G — SC2294 x1: eval over "$@" (tp-cleanup:97)

The `act()` dry-run/execute helper does `eval "$@"`. Audit every `act` call
site: if all pass simple word-vectors, drop eval and execute `"$@"` directly;
if any caller passes compound shell (pipes/redirects), switch to `eval "$*"`
and say so in a comment. Either kills the warning; direct execution is safer
if it fits.

### Bucket H — SC2209 x2: literal that looks like a command (tp-task:1452,1453)

`mode=set` → `mode='set'`. Trivial.

### The ratchet flip (last commit)

When the census is empty: in .github/workflows/ci.yml change `-S error` to
`-S warning` and rewrite the comment block to record the new contract (the
count is zero; the severity never widens again). This is the flip the file
itself promises.

## Scope

Only warning-severity findings and the ci.yml severity pin. No `info`/`style`
chasing, no disable-file-wide directives, no behavior changes beyond Bucket
C.3's investigation outcomes and Bucket F's bug fix. Goldens must not need
re-recording; if one does, the change was not behavior-preserving — stop and
reassess.
