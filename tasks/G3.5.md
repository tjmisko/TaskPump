# G3.5 — Claude gates degrade cleanly without host credentials

## Spec

A consumer driving a non-Claude agent still gets the default gate chain, and
two of its gates read Claude-specific host state. Their absent-input behavior
must be a deliberate, tested skip rather than an accident of error handling:

- `gates/claude-token-fresh`: credentials file missing or unreadable → exit 0
  with one line to stderr (`skipped: no claude credentials at <path>`), never
  exit 10. An *expired* token with credentials present still pauses as today.
- `gates/claude-usage`: same discipline for missing credentials or an
  unreachable usage endpoint — fail open with one explanatory line, per the
  GATES.md fail-open rule, and never cache a failure as a usage reading.
- `docs/GATES.md`: document the skip behavior in each gate's section, so a
  consumer reading a quiet gate line knows it is by design.

## Scope

The two gates' absent-input paths and docs. Live-credential behavior is
untouched; no new keys.

## Acceptance

- Gate suites cover: missing file, unreadable file, malformed JSON — each exits
  0 with exactly one explanatory line; expired-token and over-ceiling fixtures
  still exit 10.
- A `tp pump --dry-run` on a host with no Claude credentials shows both gates
  skipping with their one-line reasons and the feed decision unaffected by
  them.

## Completion notes (2026-08-13T23:49:54Z)

The Claude gates skip cleanly on hosts with no Claude credentials.

What landed
- lib/pump-lib.sh: apl_host_credentials_problem — one classifier for absent host
  credentials (no path, missing, unreadable, jq absent, not valid JSON), so both
  gates skip for the same reasons and word it the same way.
  apl_host_token_stale now uses it as its fail-open guard, keeping its silent
  behaviour for every non-gate caller.
- gates/claude-token-fresh: emits `claude-token-fresh: skipped: <reason>` on
  stderr and exits 0 for every absent-input shape, including readable
  credentials that carry no OAuth expiry (the shape another agent's config file
  would have). stdout stays reserved for the pause reason.
- gates/claude-usage: its unknown-bind fail-open now distinguishes "no
  credentials here" (permanent, expected for a non-Claude consumer) from "meter
  unreachable" (transient). Nothing is cached on either path — the cache is only
  written from a payload that parsed.
- libexec/tp-pump: feed_gate collects what a FEEDING gate said (GATE_NOTES) and
  print_plan shows it indented under the GATE: line. The tick loop stays quiet:
  "this host has no Claude credentials" is permanent and would otherwise print
  every 30s for days.
- docs/GATES.md: a skip subsection under each gate, plus "Where a skip shows up".

Verification
- New tests/test-claude-token-fresh.sh (13): missing / unreadable / malformed /
  no-expiry each exit 0 with exactly one line on stderr and nothing on stdout;
  expired and inside-margin still exit 10 with the reason on stdout; a fresh
  token is silent; TASKPUMP_TOKEN_GATE=0 stays silent.
- test-claude-usage.sh +7 (Test 11): no-credentials feeds with one specific line,
  malformed and unreadable likewise, the cache stays unwritten, and a seeded
  over-ceiling reading still exits 10.
- test-tp-pump.sh +3 (Test 30b2): a --dry-run with TASKPUMP_AGENT_HOME pointed at
  an empty dir plans fine, keeps GATE: feed-ok, and shows the token gate's skip
  and its reason. That is the second acceptance criterion end to end.
- Full suite: 15 suites green except the pre-existing test-entrypoint host
  artifact.

Design note
The skip line is prefixed with the gate's own name, like every other diagnostic
in this stack; the pump's existing strip_gate_prefix removes it again when it
quotes the line, so `claude-token-fresh: skipped: …` renders once, not twice.
