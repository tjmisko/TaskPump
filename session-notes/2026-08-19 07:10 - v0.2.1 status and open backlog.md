## 5. The bug backlog — documented in v0.2.1, not fixed

Every item below except **B16** is already written down somewhere in `docs/`;
B16 was measured in this session. None of them is filed. Severity is mine; the
PATCH-safety note on each is the constraint that actually decides sequencing.

### 5.1 Silent wrong-answer bugs (highest cost, hardest to notice)

**B1 — `TASKPUMP_BUILD_GATE` unset means `cargo check --workspace`.**
`docs/CONFIG.md` §3.0, §3.6. Under `--integration-trunk` on a project with no
`Cargo.toml`, `cargo check` exits non-zero before doing anything, so **every**
merge is quarantined: `reset --hard`, `build red` appended to the quarantine
file, the phase's lead task flipped to `needs-review`, the operator paged.
Verified in the release run against a fixture repo. A generic consumer adopting
`--integration-trunk` hits this on tick one.
*Fix is a default change ⇒ MINOR.*

**B2 — `TASKPUMP_USAGE_GATE` / `TASKPUMP_DISK_GATE` are overwritten before any
gate runs.** `libexec/tp-pump:265-266` hardcodes both to `1`;
`libexec/tp-pump:1042-1043` exports those hardcoded values over whatever the
operator set. Only `--no-usage-gate` / `--no-disk-gate` work. Demonstrated: a run
started with `TASKPUMP_DISK_GATE=0 TASKPUMP_USAGE_GATE=0 TASKPUMP_TOKEN_GATE=0`
hands a probe gate `disk_gate=1 usage_gate=1 token_gate=0`. No warning.
*Making the keys work ⇒ MINOR.*

**B3 — `TASKPUMP_TASKS_SUBDIR` never reaches `tp task`.** The ledger CLI defaults
`TASKPUMP_LEDGER_PROBE` before resolution, so the fallback arm is dead there
while `tp pump`, `tp monitor` and `tp dag-render` honour it. The pump's frontier
comes from that CLI, so the two halves disagree and **the pump reports the range
drained.**
*MINOR.*

**B4 — `TASKPUMP_TASK_EXT` is read by every reader and by no writer.** `tp task`
hardcodes `.md`. Setting the key desynchronises `tp monitor`, `tp dag-render` and
the container entrypoint from the tool that writes the files.
*MINOR.*

**B5 — `TASKPUMP_EXTRA_BUSY_DIRS` has no reader; `tp cleanup` reads bare
`EXTRA_BUSY_DIRS`.** The prefixed spelling is the one four places in the tree
document. The key exists to keep a reclaim sweep off a workspace that is
mid-compile, so the documented spelling **deletes exactly the build output it was
set to protect.**
*Honouring both spellings is arguably PATCH-safe.*

**B6 — the gate chain fails open on a spelling mistake.** `TASKPUMP_GATES` and
`TASKPUMP_PRE_TICK_HOOKS` are newline-separated command lines whose first word
must be an executable path. A bare gate name, or a comma-separated list, is
skipped with a warning — which reads as "the gate passed."

**B7 — `TASKPUMP_PUMP_QUARANTINE_FILE` is a log, not an exclusion list.**
Append-only, read exactly once into the graduation PR body. Phase names written
into it hold nothing back; every one is dispatched next tick.

### 5.2 Safety nets that are not attached

**B8 — the disk watchdog's cap-file path is inert two ways.**
(a) Its `REPO_ROOT` defaults to the parent of its own script dir, so from a
consumer repo with no `TASKPUMP_STATE_DIR` it writes the *installation's* cap
file while the pump reads the *workspace's*.
(b) The shared cap reader takes the file's value only when `>= 1`, so the `0` it
writes under `PAUSED`/`PANIC` falls through to the caller's `JOBS`.
Net: **disk pressure never stops the pump launching**, though the pump
advertises the watchdog as belt-and-suspenders. `docs/CLI-TOOLS.md` §"Two
reasons the cap-file path may do nothing".

**B9 — reclaim is Rust-shaped.** `tp cleanup` and `tp disk-watchdog` look for a
directory literally named `target/`. On a non-Rust workspace the panic reclaim
frees nothing — or deletes a `target/` that means something else entirely.
Same family as B1.

**B10 — `--jobs 0` ticks forever reporting health.** The pump ticks with
`status: running` and never reaches `STALL_EXIT_TICKS`. Verified in a real run
over three open tasks: it ticked until signalled. `docs/CLI-PUMP.md:98-108` calls
this "the 563-tick idle in a different costume." Until fixed, `--jobs 0` is not a
pause — stop the run, or set the cap file to `1`.

**B11 — `tp monitor` calls `docker` by name.** Every other tool resolves through
`apl_docker` (`TASKPUMP_DOCKER` → `DOCKER` → `docker`); the monitor's disk gauge,
session sweep and GRAPH liveness read all invoke a literal `docker`. On a podman
host, SESSIONS reports "no tp-agent containers running" for a healthy fleet and
GRAPH draws every claimed task as `⧗ claimed, idle`. No in-tool workaround — a
`docker` shim on `PATH` is the only lever.

**B16 — the suite writes the primary's hook mark file, and the hermeticity gate
cannot see it.** *New in this session — measured, not documented anywhere.*
Details and evidence in §6. Two halves: pin `TASKPUMP_HOOK_MARK_FILE` on the
unpinned path, and widen `tests/run-all.sh`'s before/after comparison past
`git status --porcelain`'s ignored-file blind spot.
*PATCH-safe; both halves are test-harness changes.*

### 5.3 Frozen-contract divergences (`docs/LEDGER-CONTRACT.md` §10.1)

**B12 — neither `tp task` nor `tp pump` ever exits 2**, though frozen §10
reserves `2` for "bad CLI arguments, any tool". Both route every usage error
through a `die` that exits 1. Confirmed at this revision: `tp task bogus` → rc 1.
Exit 2 *is* produced — by `bin/tp`'s unknown-command path, `tp init`,
`tp cleanup`, both watchdogs, and both runners' unknown-verb arms — so a consumer
must not read 2 as "bad arguments, generically."

**B13 — `tp pump` exit 0 does not mean drained.** Every non-loop mode also exits
0 on success: `--dry-run`, `--list`, `--once`, `--render-brief`,
`--render-resume-note`, `--help`, and `--detach` (which exits 0 in the foreground
before the run it started has ticked). Wire the systemd "0 means drained, do not
restart" rule around `--once` in cron and every tick reports a successful drain.
Key on the state file instead.

**B14 — `tp pump --phases` with no value.** §10.1 records it failing as a bash
unbound-variable error rather than a diagnostic. Not reproducible from outside a
consumer repo — the install-refusal guard fires first (rc 1) — so this one needs
re-measuring inside a real consumer before filing.

Reconciling B12/B13 changes a frozen wire protocol ⇒ **MAJOR or a deliberate
MINOR with a migration note.** They were correctly left alone in a PATCH.

### 5.4 Precondition the code does not enforce

**B15 — `--grain phase` + `--integration-trunk` requires every cross-phase
blocker's branch to exist locally** as `<prefix><phase>`, so the ancestry
question has something to answer. A range whose upstream phases predate the pump,
or were merged with their branches deleted, **walks to exit 3 while being told a
reason the repository cannot support.** Workarounds today: drop
`--integration-trunk`, run at `--grain task`, or recreate the blocker branch.
`docs/CLI-PUMP.md:405-414`.
